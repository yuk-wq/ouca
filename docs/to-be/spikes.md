### 7. 既定の Cloud プロジェクトのままで Apps Script API を呼べる

- 確かめたこと
  - `UrlFetchApp` と `ScriptApp.getOAuthToken()` で Apps Script API を呼べるか。呼べない場合に、Cloud プロジェクトの作成をオーナーに頼む必要があるか
- 結果
  - 呼べなかった（2026-11-21、個人の Gmail アカウントのテスト用スクリプト）
  - アカウントの設定（script.google.com/home/usersettings）で Apps Script API をオンにしても、`projects.deployments.list` が 403 `SERVICE_DISABLED` を返した。スクリプトに紐づく既定の Cloud プロジェクトの側で Apps Script API が無効なため
  - エラーが示す有効化の画面を持ち主のアカウントで開くと、「追加のアクセス権が必要です」（`resourcemanager.projects.get` の権限がない）となり、有効にできなかった。既定の Cloud プロジェクトは持ち主でも開けない
- 設計への影響
  - 既定の Cloud プロジェクトのままでは、スクリプトが Apps Script API で自分の中身、バージョン、デプロイを変える方式は成り立たない
  - この方式を残すには、オーナーが標準の Cloud プロジェクトを作り、API の有効化、同意画面の設定、プロジェクト番号の付け替えを行う必要がある。初回の手順が重いので採らない
  - 代わりに、スクリプトの中身は最初のコピーのまま変えず、「アプリを更新」はリリースのコードをスプレッドシートに保存するだけにし、実行のたびに保存したコードを読み込んで動かす方式（読み込み方式）を検証する（2026-11-21 決定）
  - このため、シナリオ 1〜4、6、8〜10（Apps Script API を使う方式の確かめ）は行わない。読み込み方式の確かめは `spikes/T1-1-loader/` で行う
