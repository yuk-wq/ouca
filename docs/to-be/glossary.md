# 【新設計】用語集

> 【新設計】作り直した後の姿についての文書。現行サイトの解析は `docs/as-is/` を見る。

`spikes.md` の T1-1〜T1-4 の記録は、GAS の機能を「Web アプリ」と書く。人を「持ち主」「オーナー」「デザイン担当」と書き、「確かめる」「往復」などの語も使っている（検証のときの書き方）。この文書の書き分けには合わせていない。

設計書（`design.md`）、受け渡しの文書（`delivery-flow.md`）、ワークプラン（`work-plan.md`）、検証結果（`spikes.md`）で使う言葉の説明の元。各文書の冒頭の「用語」の表には、その文書で使う言葉だけを、ここと同じ文で写す。説明を変えるときは、ここを直してから各文書の表を直す。

## 1. 書き分けの決まり

各文書の冒頭の「用語」の表にこの節の言葉を写すときは、「使う意味」の列の文を写す。

同じ言葉を2つ以上の意味で使わないように、次のとおり書き分ける。

| 言葉 | 使う意味 | ほかの意味のときの書き方 |
|---|---|---|
| 公開 | 「メニューを公開」（豆のメニューをアプリに出す操作）だけ。管理画面の「公開」も、この操作を管理画面から行うもの。公開するまで、アプリは変わらない | GAS の機能でアプリを URL で開けるようにすることは「デプロイを作る」、リリースは「リリースを出す」、関数は「外から呼べる関数」と書く。「公開リポジトリ」は GitHub の言葉なので残す |
| メニュー | 豆のメニュー（お客さんが見るもの） | スプレッドシートの上に出るこのシステムのメニューは「メニュー OUCA」と書き、その中の項目は「OUCA ▸ 初期設定」のように書く。技術検証のコードが出すメニュー（「T1-1 ローダー検証」など）は「検証コードのメニュー」と書く |
| バージョン | 修飾語を付けて使う | 「システムのバージョン」（v1.3.0 の形）、「メニューのバージョン」（`catalogVersion`）、「形式のバージョン」（`schemaVersion`）、「スクリプトのバージョン」（GAS の機能。T1-1 の最初の方式でだけ使った） |
| 段階 | 項目の種類の1つ（焙煎度 1〜7 のように数で表す項目） | 「システムを更新」の工程は番号で呼ばず、「取得」「保存」「切り替え」「メニューの公開のやり直し」の名前で書く |
| 項目 | 豆の項目（焙煎度、味わい、産地など。項目タブの行） | メニュー OUCA に並ぶものは「メニュー OUCA の項目」、Google の画面などに出る文字は「画面の文言」と書く |
| A、B | 保存場所 A、B | 検証で使った2つのアカウントは「テンプレート側のアカウント」「コピー側のアカウント」、検証用の2つのコードは「検証用のコード A、B」と書く |
| Oka、Yu | Oka は発注者（お店の人）で、アプリの管理者として管理画面を使う人。Yu はこのプロジェクトを開発する人（作業を依頼するユーザー）。実名は書かない（公開リポジトリ） | 「オーナー」「所有者」「持ち主」「デザイン担当」は、人の呼び方として使わない |
| 所有アカウント | スプレッドシートとスクリプトを所有している Google アカウント。Google の画面では「オーナー」と出る。本番では Oka のアカウント、テンプレートとテスト用スプレッドシートでは Yu のアカウントが所有アカウントになる。テンプレートをコピーすると、コピーの所有アカウントは、コピーした人（本番では Oka）のアカウントになる | 「持ち主」「所有者」は使わない。Google の画面に出る「オーナー」は「」で囲んで画面の文言として書く |
| アプリ | お客さんが注文するサイト。スマホのブラウザ（LINE の中のブラウザを含む）で開くページで、メニューを見て注文する | プログラム全体は「システム」、GAS の機能は「デプロイ」と書く。スマホのアプリは「スマホのスプレッドシートアプリ」「LINE のアプリ」のように、何のアプリかを書く |
| お客さん | 注文する人 | 「利用者」は使わない |

## 2. コードの置き方と更新

| 用語 | 意味 |
|---|---|
| システム | アプリと管理画面を動かすプログラム全体（モジュールと画面の HTML）。アプリと管理画面は1つのプログラムなので、「システムを更新」で両方が新しくなる。番号は「システムのバージョン」（v1.3.0 の形） |
| ローダー | スプレッドシートに紐づくスクリプト。外から呼べる関数（入口）、`_コード` タブからの読み込み、「システムを更新」と「前のバージョンに戻す」の処理、初期のコードを持つ。テンプレートのコピーの後は変えない。「システムを更新」でも変わらないので、ローダーの中の処理に不具合があっても、「システムを更新」では直せない |
| 復旧用のページ | 管理画面が開けないときのために、ローダーが自前で出す小さなページ。機能は「前のバージョンに戻す」と「システムを更新」の2つだけで、今のシステムのバージョンと使用中の保存場所を出す。HTML はローダーの中に持ち、モジュールを読み込まずにローダーだけで動くので、モジュールが壊れていても開ける。見た目は簡素な固定の HTML で、Figma のデザインの対象にしない |
| システムを更新 | Yu が出した最新のリリースのバンドルを取り込み、アプリと管理画面をまとめて新しくする操作。管理画面、復旧用のページ、メニュー OUCA から押せる。管理画面と復旧用のページからの更新は、リリースを取得して確認する呼び出しと、更新する呼び出しの2回になる |
| 更新の照合 | システムを更新の2回目の呼び出しで、1回目に確認したシステムのバージョンと、取り直したバンドルのバージョンを比べ、違えば何も変えずに拒否すること |
| 画面のバージョンの確認 | 画面が送ったシステムのバージョンとサーバーのシステムのバージョンを比べ、違えば操作を拒否して再読み込みを促すこと。モジュールの操作だけに行い、ローダーの処理（今のバージョン、システムを更新、前のバージョンに戻す）には行わない |
| 入口 | ローダーの中で、GAS が直接呼ぶ関数。メニュー OUCA、トリガー、デプロイの URL を開くこと、画面からの呼び出しは、すべてここから入る |
| `adminCall`、`adminUpload` | 管理画面と復旧用のページが `google.script.run` で呼ぶ入口。`adminCall` は引数の JSON の文字列で操作を選ぶ。`adminUpload` は、ファイルを受け取るために別に置く（GAS では、form を渡すときは form がただ1つの引数でなければならない）。どちらも、所有アカウント認証を通ってから動く |
| バンドル | システムのコード（モジュールと画面の HTML）を1つにまとめたファイル。GitHub のリリースに置き、「システムを更新」で `_コード` タブに取り込む |
| モジュール | バンドルのうち、サーバーで動く処理の部分。ローダーが `_コード` タブから文字列として読み込み、動かせる関数に変えて（評価して）呼ぶ |
| 初期のコード | ローダーの中に最初から入れておくバンドル。`_コード` タブに最初のバンドルを入れるときと、`_コード` タブが読めないときに使う |
| `_コード` タブ | バンドルを保存する、非表示のタブ |
| 保存場所（A、B） | `_コード` タブの中で、バンドルを1つずつ入れる2か所。片方に今のシステムのバージョンが入る。もう片方には、1つ前のシステムのバージョンがあればそれが入る（「前のバージョンに戻す」の戻す先）。「システムを更新」は、使っていない方に新しいシステムのバージョンを書く |
| 使用中の指定 | A と B のどちらの保存場所のバンドルを動かすかを書いた設定。スクリプトのプロパティに置く。スクリプトのプロパティはテンプレートのコピーに引き継がれないので、同じ内容を `_コード` タブのセルにも書く。2か所が違うときは、スクリプトのプロパティの方に従う。「システムを更新」と「前のバージョンに戻す」は、この指定を書き換えて切り替える |
| 読み込み方式 | システムのコードを `_コード` タブに置き、ローダーが動くたびに読み込んで動かす方式。スクリプトが自分の中身を書き換える方式が成り立たなかったので、T1-1（システムの自己更新）で選んだ |
| リリース | GitHub の機能。コードのある時点に番号（タグ。v1.3.0 など）を付け、バンドルを添付して出す。Oka は「システムを更新」で、最新のリリースのバンドルを取り込む |
| テンプレート | Yu が作る、初期設定済みのスプレッドシート。Oka は「コピーを作成」でこれを複製して、本番のスプレッドシートにする |
| テスト用スプレッドシート、テスト用スクリプト | Yu が持つ、ダミーデータだけのスプレッドシートと、それに紐づくスクリプト。`npm run push:test` でローダーを送り、GAS の上の動きを確認する |

## 3. GAS の仕組み

| 用語 | 意味 |
|---|---|
| 外から呼べる関数 | GAS では、スクリプトの一番外側に書いた関数を、メニュー OUCA、トリガー、画面から名前で呼べる。このシステムのデプロイは誰でも開ける設定なので、知らない人も画面からこれらの関数を呼べる。名前の末尾が `_` の関数は、画面からは呼べない |
| 所有アカウント | スプレッドシートとスクリプトを所有している Google アカウント。Google の画面では「オーナー」と出る。本番では Oka のアカウント、テンプレートとテスト用スプレッドシートでは Yu のアカウントが所有アカウントになる。テンプレートをコピーすると、コピーの所有アカウントは、コピーした人（本番では Oka）のアカウントになる |
| 所有アカウント認証 | 開いた人、または関数を呼んだ人が、スプレッドシートの所有アカウントかの判定。`adminCall`、`adminUpload`、メニュー OUCA の操作は、これを通ってから動く |
| active、effective | GAS の `Session.getActiveUser()`（関数を呼んだ人）と `Session.getEffectiveUser()`（関数を実行している人）のメールアドレス。所有アカウント認証で比べる。個人の Gmail のアカウントでは、所有アカウントでない人が呼ぶと active は空になる（T1-3（シートの機能の技術検証）） |
| スクリプトのプロパティ | スクリプトごとに値を保存しておける、GAS の設定の置き場。シートには出ず、テンプレートのコピーには引き継がれない |
| トリガー | 決まったとき（シートを開いた、編集した、決めた時刻になった）に、関数を自動で動かす GAS の仕組み |
| シンプルトリガー | 関数に決まった名前（`onOpen` など）を付けるだけで動くトリガー。承認の前でも動くが、できることが限られる |
| インストール型のトリガー | スクリプトが作って登録するトリガー。作った人の権限で動く。テンプレートのコピーには引き継がれないので、初期設定で作る。決めた時刻や間隔で動くものを「時間主導のトリガー」と呼ぶ |
| `triggerUid` | トリガーが動いたときに関数に渡される、トリガーごとの ID。このスクリプトが作ったトリガーから呼ばれたかを確認するのに使う |
| デプロイ | スクリプトを URL で開けるページにする GAS の設定と、その結果。アプリと管理画面は、同じデプロイの URL（管理画面は引数つき）で開く。Oka が初回に作り、作り直さないので、URL は変わらない（所有アカウント認証が通らないときは、管理画面を2つ目のデプロイで出す。T1-6（管理画面の開き方と Google ドライブの許可の技術検証）で検証する） |
| `google.script.run` | アプリと管理画面（ブラウザ）から、サーバーの関数を呼ぶ GAS の仕組み。呼べるのは外から呼べる関数だけ（名前の末尾が `_` のものは除く） |
| 承認、承認画面 | スクリプトが初めて権限の要る処理をするときに Google が出す画面（承認画面）で、所有アカウントでログインした人が権限を許可すること |
| マニフェスト | スクリプトの設定ファイル（`appsscript.json`）。スクリプトが求める権限の範囲や、デプロイの設定を書く。ローダーの側にあるので、「システムを更新」では変えられない |
| 権限の範囲（`oauthScopes`） | スクリプトが使ってよい Google の機能の一覧（スプレッドシートの読み書き、メールの送信など）。マニフェストに書き、所有アカウントでログインした人が承認の画面で許可する |
| キャッシュ（`CacheService`） | GAS の一時的な保存の場所。読み込みを速くすることと、二重送信を見分けることに使い、最長6時間で消える |
| `LockService` | ロックを取る処理どうしが、同時に動かないようにする GAS の仕組み。注文、管理画面の書き込み、「システムを更新」で使う |
| Apps Script API、既定の Cloud プロジェクト | Apps Script API は、スクリプトの中身やデプロイを外から変える Google の仕組み。スクリプトごとに自動で作られる Cloud プロジェクト（既定の Cloud プロジェクト）では、この API を有効にできなかった（T1-1） |
| clasp | 手元のコードを Apps Script のスクリプトに送る、Google の道具。このプロジェクトでは、テスト用スクリプトに送るときだけ使う |

## 4. シートと画面の言葉

| 用語 | 意味 |
|---|---|
| 項目 | 豆に付ける情報の種類（焙煎度、甘味、味わい、産地など）。項目タブに1行ずつ書き、Oka が管理画面の表示設定で足したり名前を変えたりできる |
| 表示設定 | アプリの見え方を決める設定。項目、選択肢、区分け、絞り込み、並べ替え、文言を含む。管理画面の表示設定の画面で下書きとして直し、「メニューを公開」でアプリに出る |
| 段階、分類、はい・いいえ | 項目の種類。段階は 1〜N の数で表す（焙煎度 1〜7 など）。分類は候補から選ぶ（味わいなど）。はい・いいえはチェックボックスで表す |
| 区分け | 段階の項目で絞り込むときに使う、範囲の名前（焙煎度 1〜2 を「浅め」とするなど） |
| まとめ（項目タブの列） | 複数の段階の項目を、1つのかたまりとして並べて出すための名前（「味のバランス」など） |
| 管理画面 | Oka が設定、豆、公開、注文を管理する Web ページ。所有アカウントでログインした人だけが操作できる。アプリと同じシステムの一部で、デプロイの URL で開く |
| 下書き | 管理画面で保存したが、まだ公開していない内容 |
| 下書きの照合 | 管理画面の「公開」で、変更点の確認の呼び出しが返した下書きを表す値（更新番号の組かハッシュ。形は T2-5）を公開の呼び出しに送り、今の下書きと比べること。違えば公開せずに、確認からやり直させる。メニュー OUCA の「メニューを公開」は確認の画面がないので、照合しない |
| 更新番号 | 管理画面が書く行（豆、カテゴリ、設定など）が持つ、保存するたびに1増える数。管理画面は読んだときの更新番号を送り、保存のときに変わっていれば、保存せずに知らせる。PC とスマホで同時に開いたときに、先の保存を上書きしないために使う |
| メニュー OUCA | スプレッドシートの上に出る、このシステムのメニュー。「OUCA ▸ メニューを公開」のように、中の項目を押して操作する。初期設定の前は「初期設定」など少しの項目だけが出る |
| 名寄せ | 書き方の違う同じ人の名前（「佐藤」と「佐藤花子」など）を、1人の名前にまとめること。スクリプトが候補を出し、Oka が管理画面で確認する。結果はお客さんタブに残る |
| 端末ID | お客さんの端末（ブラウザ）ごとに作る、名前の入っていない ID。同じ端末からの注文だと分かる手がかりとして、名寄せに使う |
| お気に入り（ハート） | お客さんがアプリで豆に付ける印。お客さんの端末（ブラウザ）に保存し、注文と一緒に送る。LINE の中のブラウザでは、開き直すと消える（T1-4（Web アプリの動作）） |
| 受付番号 | 注文ごとに付ける番号。「年月日 + その日の連番」（例 `261121-03`） |
| DB タブ | 注文の一覧を置くタブ。1行が1件の注文 |
| ダッシュボード | 豆ごとの注文量、週ごとの件数と金額、人ごとの好みを集計した表とグラフ。シートのタブと、管理画面の画面の両方の名前に使う |
| 絞り込み、並べ替え | アプリでお客さんが豆を探すための操作。何で絞り込み、何で並べ替えられるかは、表示設定の絞り込みタブと並べ替えタブで決める |
| 使わない | もう扱わない豆とカテゴリに付ける印。注文と集計が豆の ID やカテゴリの名前で結び付くので、消さずに「使わない」にする。今週メニューに出すかの「表示」とは別 |
| 公開の履歴 | 「メニューを公開」ごとに、公開日時と、公開した内容と、形式のバージョンを残したもの |
| アイコンセット | Yu が Figma で作る、豆とカテゴリと操作（ハート、閉じる、矢印など）のアイコンの一式。Oka は管理画面で選ぶだけで、増やせない |
| 初期設定 | メニュー OUCA の項目。空のスプレッドシートやテンプレートのコピーに、タブ、トリガー、使用中の指定などを作る。何度押しても同じ結果になる |
| 管理タブ、画像のボタン | 管理画面を作る前の設計で、Oka がシートで操作するために置く予定だったタブと、関数を割り当てた画像。管理画面を作るので置かない |
| `_公開データ` タブ | 「メニューを公開」が書く、アプリに出すメニューのデータ（JSON）を置く非表示のタブ |

## 5. 開発の道具と進め方

| 用語 | 意味 |
|---|---|
| TypeScript、Preact、Vite、esbuild、Vitest | 開発の道具。TypeScript は型を書ける JavaScript、Preact は画面を部品で組み立てる道具、Vite は画面を手元で表示して1つの HTML にまとめる道具、esbuild はサーバーのコードを1つにまとめる道具、Vitest はテストの道具 |
| モック、偽物 | どちらも本物の代わりに、決まった値を返すもの。モックは手元で画面を確認するときに使い（`mock/catalog.json`）、偽物はテストで GAS の機能（`SpreadsheetApp` など）の代わりに置く |
| 純粋な関数 | 受け取った値だけから結果を返し、シートや画面に触れない関数。GAS がなくてもテストできる |
| メインのセッション、実行役、レビュー役 | Claude Code の役割。メインのセッションは作業を設計して判断し、実行役（spec-writer、implementer）は仕様やコードを書き、レビュー役（reviewer）は成果物を確認する（`CLAUDE.md`） |
| 依頼文、依頼文の型 | メインのセッションが実行役とレビュー役に渡す作業の指示。書く項目（依頼文の型）は `work-plan.md` §1.3 にある |
| 論点 | 実行役が報告する、自分で決めなかった事項のうち、決めた結果で次の行動が変わるもの。メインのセッションが決めるか、Yu に確かめる |
| T 番号、D 番号 | ワークプランのタスクの番号（T1-2 など）と、Yu に決めてもらうことの番号（D-1 など）。対応は `work-plan.md` §3、§4 にある。文書の中では、初めて出る位置でタスクの名前を添える |
| § | 文書の節の番号。「`delivery-flow.md` §5.3」は、受け渡しの文書の 5.3 の節を指す |
