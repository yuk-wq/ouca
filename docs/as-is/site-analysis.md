# 【現行】サイトの解析（2026-11-21 時点）

> 【現行】作り直す前の現行サイトについての文書。新しい設計は `docs/to-be/` を見る。

対象: 現行の注文サイト（オーナーの Web アプリ。URL は公開しない）

記号の意味
- 【確認】実ページ、通信、コードで確かめた事実
- 【推測】状況から推した内容。サーバー側コードとスプレッドシートは未入手なので、裏側の構造はすべて推測になる

証拠ファイルは `_work/raw/` に置く（一覧は末尾）。

## 1. 全体構成

```
[スマホブラウザ]
  └ script.google.com/.../exec        GAS の外枠ページ（title, viewport, 警告バー）
      └ iframe #sandboxFrame           *.googleusercontent.com/userCodeAppPanel
          └ userHtml（= index.html）    画面とロジックはすべてここ。素の JS、ライブラリなし
                │ google.script.run
                ▼
          GAS サーバー関数  doGet / getMenuData / testMenuData / submitOrder
                │
                ▼
          スプレッドシート（【推測】「メニュー設定」タブ + 注文記録タブ）
```

- 【確認】GAS の Web アプリ。`sandboxMode: IFRAME_SANDBOX`、`callbackTimeout: 390000`
- 【確認】未ログインの curl で HTML が返るので、アクセス権は「全員」。実行ユーザーは【推測】「自分（オーナー）」。匿名ユーザーがスプレッドシートに書き込めているため
- 【確認】外枠ページに `<title>今週のコーヒー</title>` と viewport の meta がある。【推測】doGet は `HtmlService.createHtmlOutputFromFile('index')` に `.setTitle('今週のコーヒー').addMetaTag('viewport', ...)` を付けて返している
- 【確認】画面の最上部に Google の警告バー（「このアプリケーションは Google ではなく、ユーザーによって作成されたものです」）が出る。個人の Gmail アカウントで公開した GAS では消せない。スマホでは常に縦の領域を使う
- 【確認】クライアントから呼べる関数（`functionNames`）は `doGet`, `getMenuData`, `testMenuData`, `submitOrder` の4つ。GAS では末尾が `_` でないグローバル関数はすべて外から呼べる

## 2. サーバー関数

### getMenuData()
- 【確認】引数なし。戻り値の形（実データは `_work/raw/getMenuData_2026-11-21.json`）

```
{
  cats:      [{cat: "STANDARD", price: 500}, {cat: "SPECIAL", price: 600}, {cat: "DECAF カフェインレス", price: 650}],
  shipping:  300,
  maxGrams:  450,
  step:      50,
  minGrams:  100,
  maxTypes:  3,
  notice:    "",          // 空でなければ見出し下に赤字で出る
  items: [ {
    order, cat, price, emoji, name, isNew, tags, desc,
    roast,                // 1〜7（浅→深）
    sweet, acid, body, aroma   // 1〜5
  }, ... ]               // 現在 8 件
}
```

- 【確認】`items[].price` は全件が所属カテゴリの `cats[].price` と同じ値。金額計算は `items[].price` を使う
- 【確認】`order` は 1,2,3,4,5,7,8,9 で 6 が欠けている。【推測】シートに行はあるが、非表示（売り切れ等）のフラグで除外されている
- 【確認】`families` は返っていない（後述の「渡された HTML」が使う項目）
- 【推測】カテゴリ名と価格、送料、上限値、お知らせ文はシート上の設定欄から読んでいる。渡された HTML のコメントに「メニューはスプレッドシート『メニュー設定』タブから読み込む」とある

### testMenuData()
- 【確認】呼ぶと `null` を返す。【推測】動作確認用の関数が公開されたまま残っている

### submitOrder(payload)
- 【確認】クライアントが送る内容

```
{ name: "岡本", delivery: "hand" | "post", note: "...", items: [{name: "豆の名前", grams: 150}, ...] }
```

- 価格は送らない。【確認】成功時の戻り値から `res.total` と `res.grams` を画面に出しているので、サーバー側で合計を計算し直している
- 【未確認】実注文が入るため呼んでいない。次の点は不明
  - `res.total` に送料を含むか
  - サーバー側で上限（3種類・450g・50g 単位）を検証しているか
  - 注文の記録先（シート名、列）、オーナーへの通知（メール等）の有無
- 豆の特定に `name` を使っている。【推測】サーバーは名前でメニュー行を引いて価格を出している。メニュー名を変えると、編集前に開いていた画面からの注文が失敗またはずれる可能性がある

### 通信の形式（参考）
- 【確認】`google.script.run.X()` は外枠ページから `POST /macros/s/<id>/callback?nocache_id=N&token=…` になる。本文は `request=["X","[]",null,[0],null,null,1,0]`、応答は `)]}'` の後に `[["op.exec",[0,"<JSONの文字列>"]],["di",<ms>]]`
- 【確認】`di` は処理時間と見られる値で、getMenuData は 1466〜1633ms。初回表示で「読み込んでいます…」が1.5秒以上出る

## 3. 画面とロジック（公開中の版）

### 画面の並び（上から）
1. タグライン、見出し「COFFEE MENU」、お知らせ（`notice` があるときだけ）
2. 「ご注文の前に」の案内枠（文言は HTML に直書き）
3. 固定バー（`.bar`、`position: sticky; top: 8px`）。何か選ぶまで非表示
4. 絞り込み（常時表示）: 焙煎度（すべて/浅め/中/深め）、味わい（すべて/甘味/酸味/コク/香り）、デカフェのみ
5. メニュー（カテゴリ見出し + カード）
6. 注文フォーム: 名前、受け取り方法（手渡し/郵送 +¥300）、備考、選んだものの一覧、注文ボタン、完了表示、リセット

### カード
- 1行目: 絵文字、名前、NEW バッジ（`isNew`）
- 2行目: タグ文字列と、焙煎度の小さな7段階ドット
- 量のボタン: `gramChoices()` = `minGrams` から **300（直書き）** まで `step` 刻み → 100/150/200/250/300g の5個。選択中は先頭に「×」（取消）が付く
- 「詳細（味わい・焙煎度）▾」で説明文、焙煎度スケール、甘味・酸味・コク・香りの5段階を開閉。開閉状態は `openMap` に保持
- 選択中のカードは `.sel` で枠と背景が変わる

### 状態と計算
- 状態は `qty[豆の名前] = グラム`、`delivery`、絞り込みの変数だけ。保存（localStorage 等）はしないので、再読み込みで消える
- `totals()`: 種類数 k、合計グラム g、豆代 t = Σ(グラム / 100 × price)
- 送料: 郵送かつ豆代 > 0 のときだけ `MENU.shipping`
- 上限: 量ボタンを押した時点で「押した後の g が maxGrams 超」か「押した後の k が maxTypes 超」なら選択させない。代わりにそのカードを赤枠にして「⚠ 3種類までです」または「⚠ 合計450gまでです（あとNgまで）」を2.6秒出す
- 固定バー: 「k種類 ／ gg」「合計金額（送料込み）」「あとN種類・Ngまで選べます」または「上限いっぱいです」
- 注文ボタンが押せる条件: 豆代 > 0、上限超えなし、名前が空でない。固定バーの「注文へ進む」は名前を問わず、フォームまでスクロールするだけ

### 絞り込みの判定
- 焙煎度: 浅め = 1〜2、中 = 3〜4、深め = 5〜7
  - 【確認】現在のデータの焙煎度は 3,6,4,6,3,3,3,5。「浅め」を押すと0件になり「条件に合う豆がありません」が出る
- 味わい（甘味等）: その値が4以上、またはその豆の4項目の中で最大なら表示
- デカフェ: カテゴリ名が `DECAF` で始まるかで判定（カテゴリ名の表記に依存）
- 絞り込みで隠れた豆も、選択済みなら合計に入ったまま残る

### 送信後
- 成功: 完了表示（名前、選んだもの、受け取り、`res.total`、`res.grams`、「LINEで連絡します」）を出し、ボタンを「注文済み」で無効化する
- 失敗: エラー文を `#warn` に出し、ボタンを元に戻す
- 「入力をリセットしてもう一度試す」: 量と受け取り方法だけ戻す。名前、備考、絞り込み、開閉状態は残る

## 4. 見つかった問題と注意点

不具合（または不具合になり得る点）
- 注文の二重送信: 送信成功の後でも量ボタンや名前欄を触ると `updateSummary()` が注文ボタンを再び有効にする（文言は「注文済み」のまま）。押すと同じ注文がもう一度送られる
- 量ボタンの上限 300g が直書き。`maxGrams` や `step` をシートで変えても選択肢と合わない
- 案内文（「3種類・合計450gまで」「1種類100gから、50g単位」「送料¥300」）と郵送ボタンの「+¥300」が HTML に直書き。シートの設定を変えると画面の文言と計算がずれる
- 「浅め」の絞り込みが今のメニューでは必ず0件
- 名前で豆を特定しているので、メニュー名の変更と注文の受け付けがぶつかると、注文が失敗するか別の豆に結びつく可能性がある（サーバー実装による）
- カテゴリ名と価格を `innerHTML` で差し込んでいる。シートの編集者しか触れない値なので危険度は低い

使い勝手の面で気になる点（UI 改善の材料）
- 最上部の Google 警告バーと、案内枠、絞り込みが常に表示されるため、スマホの1画面目に豆のカードがほぼ出ない
- 豆ごとの価格がカードに出ない（カテゴリ見出しの「100g 500円」だけ）
- 量ボタンが5個並び、100〜300g の差が金額でどう変わるか押すまでわからない
- 上限エラーは押した後に2.6秒だけ出る。押せない量を事前に示していない
- 名前未入力では注文ボタンが無効になるだけで、理由が出ない
- 郵送を選んでも住所欄がない（LINE で確認する前提）。手渡しの日時も備考に任せている
- 初回のメニュー読み込みに1.5秒前後かかる（GAS の処理時間）

## 5. 渡された index.html と公開版の違い

渡された `~/Downloads/index.html`（`_work/raw/provided_index.html`）は公開版（`_work/raw/live_userHtml.html`）と一致しない。差分は `_work/raw/provided_vs_live.diff`。渡された方が新しい開発版と見られる。

渡された版で追加、変更された点
- 絞り込みを「絞り込み ▾」ボタンで開閉する（初期は閉じる）。ボタンに選択中の条件を「絞り込み：中・甘味」の形で出す
- 絞り込みの行を「味わい」（`families` から自動生成）と「強さ」（甘味/酸味/コク/香り、公開版の「味わい」行）に分けた
- 固定バーに、郵送のとき「送料込みで100gあたり約¥N」を出す
- 案内枠に送料と100gあたり単価の説明を1行追加

食い違い
- 渡された版は `items[].families`（配列）を使うが、公開中の `getMenuData` は返していない。今の裏側で渡された版を動かすと「味わい」行は「すべて」だけになる
- 【推測】依頼者の手元では、シートとサーバー側にも `families` 列の追加が進んでいる

方針（2026-11-21）
- 当初は渡された版を起点に改善する方針だったが、GAS で一から作り直す方針に変えた（`docs/to-be/design.md`）。渡された版の機能（絞り込みの開閉、味わいの分類、100gあたり単価）は新しい設計に引き継ぐ

## 6. スプレッドシートの構造（推測）

## 7. UI 改善を進めるうえでの制約

- 改善版も GAS の `HtmlService` で配信する前提なら、HTML/CSS/JS は1ファイル（または `<?!= include() ?>` で分割）に収める。外部 CDN は読めるが、iframe の中で動く
- サーバーとのやり取りは `getMenuData()` と `submitOrder(payload)` の2つで足りる。この2つの入出力を変えなければ、裏側に手を入れずに画面だけ差し替えられる
- 手元で確認するときは `google.script.run` の代わりに `getMenuData_2026-11-21.json` を返すモックを用意する
- 警告バーは GAS の外枠が出すので、HTML 側では消せない
