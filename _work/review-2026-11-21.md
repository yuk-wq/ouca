# design.md v1 技術レビューの取捨（2026-11-21）

レビューはサブエージェントが実施。v1 → v2 の改訂理由の記録。

## 採用

| 指摘 | 判断 | v2 での扱い |
|---|---|---|
| 1-1 匿名で全グローバル関数を呼べる | 正しい（GAS の仕様） | 公開名は doGet / getCatalog / placeOrder / onOpen / onEdit だけ。ほかは末尾 `_`。管理操作はオーナー確認で守る |
| 1-2 セルへの数式注入 | 正しい | 利用者の文字は先頭に `'`、長さ制限、制御文字除去 |
| 1-3 onEdit キャッシュ消去は漏れる、入力途中が公開される | 正しい（onEdit は手入力と貼り付けだけ） | 「メニューを公開」で検証と反映を1つに。公開データは非表示シート |
| 1-4 バインドは付け替え不可 | 正しい | 移行の最初に、現行スクリプトがバインドかを確認する |
| 1-5 Date を返すと null | 正しい | getDisplayValues で読み、API は JSON 文字列で返す |
| 1-6 埋め込みの壊れ方 | 正しい | 置換は関数で、`<` をエスケープ、`application/json` に入れる。リンクは `_top` |
| 1-7 iframe の localStorage | 正しい | 補助扱い、try/catch |
| 1-8 冪等、受付番号 | 採用 | CacheService + TextFinder、受付番号に年、メールはロック外 |
| 1-9 version の項目がない | v1 の不整合 | catalogVersion と CHANGED を追加 |
| 1-10 /dev も本番シートに書く | 正しい | テスト用スプレッドシートを分ける |
| 1-11 clasp 3 は TS を変換しない | 正しい | esbuild で1ファイル、入口はトップレベル関数 |
| 軽微 §5 と §2.5 の矛盾 | v1 の不整合 | 選択肢タブがプルダウンの元になるので「選択肢にない値」は起きにくい。公開時に検出 |
| 2 属性スキーマは初心者に重い | 同意 | 汎用は「分類」だけ。焙煎度・味の4項目・区分け・並べ替え名はコード固定 |
| 2 「分類を追加」ダイアログ | 採用 | 3か所（選択肢の列、豆の列、絞り込みの行）を同時に作る |

## 実装時に確かめる（未確認）

- メニュー（addItem）から末尾 `_` の関数を呼べるか。呼べなければ公開名にしてオーナー確認で守る
- Apps Script から複数選択のプルダウンを設定できるか。できなければ、オーナーに入力規則の画面でオンにしてもらう手順を出す
- onEdit が行の削除で動かないこと（「未公開の変更あり」の表示が漏れるだけで、実害はない）
- /dev の実行ユーザー

## v3 での見直し（ユーザーの判断）

- v2 で採用した「段階、区分け、並べ替えの名前をコードで固定」は、ユーザーの判断で取りやめた。HTML への直書きを減らし、項目・段階・区分け・絞り込み・並べ替え・文言をフォーム形式のタブで設定できるようにした
- 初心者向けの配慮（英字キーや記法をなくす、1行1件、プルダウンとチェックボックス、公開時の検証）は v2 のまま保つ
- 段階の数を可変にしたので、Figma の段階部品は 3〜10 段階で崩れない形を求める
