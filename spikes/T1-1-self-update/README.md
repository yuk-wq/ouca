# T1-1 アプリの自己更新の検証

Issue #7。オーナーが「OUCA ▸ アプリを更新」を1回押すだけで最新のバージョンを取り込める設計が、GAS で成り立つかを確かめる。

この検証では、テスト用スプレッドシートのスクリプトが、GitHub のリリースから新しいコードを取ってきて、自分の中身を置き換える。置き換え前のコードを「コード A」、置き換え後のコードを「コード B」と呼ぶ。2つの違いは名前だけで、どちらで動いたかがメニューの名前、ログ、Web アプリの画面に出る。

前半はデザイン担当が操作する手順、後半は開発者向けの補足になっている。

## 操作する場所

| 場所 | 開き方 | ここで見るもの、すること |
|---|---|---|
| テスト用スプレッドシート | Google ドライブから、U-1 で作ったものを開く | 操作の大半はここで行う |
| メニュー「T1-1 検証（コード A）」 | スプレッドシートの上のメニューで、「ヘルプ」の右にある | 検証の操作を押す。括弧の中が、今のスクリプトの中身がコード A か B か |
| 「T1-1 検証ログ」タブ | スプレッドシートの下のタブ。初めて操作したときにできる | 押した操作の結果が1行ずつ増える。「結果」の列は OK、NG、停止（意図）のどれか |
| 「T1-1 公開データ」タブ | 同じく下のタブ。「メニューの公開の代わり」を初めて押したときにできる | 「動いたコード」の列で、A と B のどちらで動いたかを見る |
| Web アプリのタブ | 手順 3 でログに出る URL を、ブラウザの新しいタブで開く | 画面に「コード A」か「コード B」と出る。お客さんが見る画面の代わり |
| Apps Script のエディタ | スプレッドシートの上のメニュー「拡張機能 ▸ Apps Script」 | デプロイ（Web アプリの公開の設定）の確認とアーカイブだけに使う。コードは直さない |
| Apps Script の設定 | https://script.google.com/home/usersettings | 「Google Apps Script API」をオンにする |

## メニューの各項目がすること

| 項目 | すること |
|---|---|
| 取得を試す（固定の URL 2 つ） | GitHub のリリースにある新しいコード（コード B）を、ダウンロードできるかだけを試す。スクリプトの中身は変えない |
| アプリを更新（段階 1〜4） | 本番の「アプリを更新」と同じ流れを、4つの段階で進める。1 取得、2 中身をコード B に置き換え、3 バージョン番号を作る、4 Web アプリをそのバージョンに切り替え |
| アプリを更新（段階 1〜5） | 上の4段階に、5 メニューの公開のやり直しを足す。段階 5 は「公開データ」タブに1行書き、1分後に同じことをするトリガーも作る |
| 止める設定 ▸ 段階 N の後で止める | 次に「アプリを更新」を押したとき、段階 N の後でわざとエラーで止める。途中で止まった場合を再現するため。1回止めると設定は消える |
| 止める設定 ▸ 止めない | 止める設定を取り消す |
| 取得先を切り替える（spike / latest） | 取ってくる URL を切り替える。通常は使わなくてよい |
| メニューの公開の代わり（押し直し） | 「公開データ」タブに、今動いたコードが A か B かを1行書く。本番の「メニューを公開」の代わり |
| 初期の Web アプリを作る | 今のコードでバージョン番号を作り、Web アプリを公開する。最初に1回だけ押す |
| 前のバージョンに戻す | 更新を始める前のコード（コード A）に、スクリプトの中身と Web アプリを戻す |
| 状態を見る | 今の状態（中身が A か B か、Web アプリの向き先、バージョンの数、待っているトリガーの数）をログに書く |
| 記録を消す | 更新の途中の記録と止める設定を消す。次の確認を最初からやり直すために押す |

## 手順

所要時間は 30〜40 分ほど。画面が手順と違ったら、その時点の画面の文言をメインのセッションに渡す。

### 1. Apps Script API をオンにする（1回だけ）

- 場所: Apps Script の設定
- 操作
  1. https://script.google.com/home/usersettings を開く
  2. 「Google Apps Script API」がオフなら、スイッチを押してオンにする

### 2. 初回の承認

- 場所: テスト用スプレッドシート
- 操作
  1. スプレッドシートを開く。開いていたら、ブラウザで再読み込みする
  2. 数秒待ち、メニュー「T1-1 検証（コード A）」が出たことを確かめる。出なければもう一度再読み込みする
  3. 「T1-1 検証（コード A）▸ 状態を見る」を押す
  4. 「承認が必要です」と出たら「OK」（または「続行」）を押す
  5. アカウントを選ぶ画面で、スプレッドシートの持ち主のアカウントを選ぶ
  6. 「このアプリは Google で確認されていません」と出たら、左下の「詳細」を押し、下に出る「（プロジェクト名）（安全ではないページ）に移動」を押す
  7. 権限の一覧が出たら、チェックボックスがあれば「すべて選択」を押し、「続行」（または「許可」）を押す
  8. スプレッドシートに戻り、もう一度「状態を見る」を押す。承認した直後は、押した操作が動かないことがあるため
- 確かめること
  - 下のタブに「T1-1 検証ログ」ができ、行が書かれている

### 3. 古いデプロイを片付け、最初の Web アプリを作る

- 場所: テスト用スプレッドシート、Apps Script のエディタ、Web アプリのタブ
- 操作
  1. 「T1-1 検証ログ」タブの一番下の行の「詳細」に「デプロイ 0 件」とあるかを見る
  2. 1件以上あれば、アーカイブする
     - 「拡張機能 ▸ Apps Script」でエディタを開く
     - 右上の「デプロイ ▸ デプロイを管理」を押す
     - 左の一覧のデプロイを1つずつ選び、右上の「アーカイブ」を押す
     - スプレッドシートに戻り、「状態を見る」で 0 件になったことを確かめる
     - 残しておくと、「前のバージョンに戻す」で本体のコードに置き換わるおそれがある
  3. 「初期の Web アプリを作る」を押す
  4. ログの一番下の行に出る `https://script.google.com/macros/s/…/exec` の URL をコピーし、ブラウザの新しいタブで開く。このタブは最後まで開いたままにする
- 確かめること
  - Web アプリのタブに「コード A」と出る

### 4. リリースを取れるか試す

- 場所: テスト用スプレッドシート
- 操作
  1. 「取得を試す（固定の URL 2 つ）」を押す
- 確かめること
  - ログに行が増える。中身の読み取りはメインのセッションが行う

### 5. 中身を置き換えた直後の状態を見る

途中で止めて、スクリプトの中身だけがコード B になり、Web アプリがまだコード A の状態を作る。

- 場所: テスト用スプレッドシート、Web アプリのタブ
- 操作
  1. 「止める設定 ▸ 段階 2 の後で止める」を押す
  2. 「アプリを更新（段階 1〜5）」を押す
  3. エラーのダイアログが出る。わざと止めたもので、正常な動き。「閉じる」を押す
  4. 「状態を見る」を押す
  5. スプレッドシートを再読み込みする
  6. 「メニューの公開の代わり（押し直し）」を押す
  7. Web アプリのタブを再読み込みする
  8. 「前のバージョンに戻す」を押し、続けて「記録を消す」を押す
  9. スプレッドシートを再読み込みする
- 確かめること
  - 手順 5 の後、メニューの名前が「コード B」になっている
  - 手順 6 の後、「公開データ」タブの動いたコードが B
  - 手順 7 の後、Web アプリのタブは「コード A」のまま
  - 手順 9 の後、メニューの名前が「コード A」に戻っている

### 6. 最後まで更新する

- 場所: テスト用スプレッドシート、Web アプリのタブ
- 操作
  1. 「アプリを更新（段階 1〜5）」を押す。エラーなく終わる
  2. Web アプリのタブを再読み込みする
  3. 3〜5分待ってから「状態を見る」を押し、ログの詳細が「時間主導のトリガー: 0」になっているかを見る。1 のままなら、さらに待ってから押し直す（トリガーは数分遅れることがある）
  4. 0 になったら、「メニューの公開の代わり（押し直し）」を押す
  5. 「前のバージョンに戻す」を押し、続けて「記録を消す」を押す
  6. スプレッドシートを再読み込みする
- 確かめること
  - 手順 2 の後、Web アプリのタブが「コード B」になり、URL は変わっていない
  - 手順 4 の後、「公開データ」タブに、段階 5、時間主導のトリガー、押し直しの3行がある
  - 手順 6 の後、メニューの名前が「コード A」に戻っている
- 注意
  - トリガーの行が付く前に戻すと、トリガーが戻した後のコードで動き、結果を読み違える

### 7. 途中で止まっても続きから進めるか

次の流れを、N を 1、2、3、4 に変えて4回繰り返す。

- 場所: テスト用スプレッドシート
- 操作
  1. 「止める設定 ▸ 段階 N の後で止める」を押す
  2. 「アプリを更新（段階 1〜4）」を押す。エラーのダイアログが出るので「閉じる」を押す
  3. もう一度「アプリを更新（段階 1〜4）」を押す。今度はエラーなく終わる
  4. 「前のバージョンに戻す」を押し、続けて「記録を消す」を押す
  5. スプレッドシートを再読み込みする
- 確かめること
  - 手順 3 のログに「段階 N は済み。飛ばす」と出ている

### 8. 別のアカウントで Web アプリを開く（任意）

- 場所: ブラウザのシークレットウィンドウ
- 操作
  1. シークレットウィンドウで、別の Google アカウントにログインする
  2. Web アプリの URL を開く
- 確かめること
  - 画面の `getEffectiveUser` が、スプレッドシートの持ち主のメールアドレス（先頭2文字とドメインだけ）になっている

### 9. 結果を渡す

- 場所: テスト用スプレッドシート、メインのセッションとのチャット
- 操作
  1. 「T1-1 検証ログ」タブを開き、左上の角（A と 1 の間の四角）を押して全体を選び、コピーしてチャットに貼る
  2. 「T1-1 公開データ」タブも同じようにして貼る
  3. 手順 8 を行った場合は、Web アプリの表示を「持ち主と同じアドレスだった」のように一言で書く
- 補足
  - チャットには URL やメールアドレスをそのまま貼ってよい。リポジトリは公開なので、`docs/to-be/spikes.md` に書くときは、メインのセッションが Web アプリの URL、デプロイ ID、メールアドレスを伏せる

片付けは、メインのセッションが結果を確かめた後に行う（下の「片付け」）。

### 編集者として作った場合の確認（任意、T1-2 とまとめて行う）

別のアカウントをテスト用スプレッドシートの編集者にして、次の順に操作する。検証の操作の守りは「Web アプリから呼ばれたら止める」だけにしてあり、スプレッドシートの持ち主との照合は入れていないので、編集者もメニューを押せる。

1. 編集者のアカウントで、手順 1 と手順 2 を行う
2. 持ち主が「記録を消す」を押す。編集者が「アプリを更新（段階 1〜4）」を押す。Web アプリを、持ち主と別のアカウントで開き、`getEffectiveUser` を写す
3. 持ち主が「前のバージョンに戻す」「記録を消す」を押す。持ち主がエディタの「デプロイ ▸ デプロイを管理」で既存のデプロイをアーカイブする。編集者が「初期の Web アプリを作る」を押し、そのログの URL を開いて `getEffectiveUser` を写す
4. 編集者が作ったデプロイを持ち主がアーカイブし、持ち主が「初期の Web アプリを作る」を押して元に戻す

## 片付け

メインのセッションが結果を確かめた後に行う。

1. テスト用スプレッドシートで「記録を消す」を押す（次の手順の後はメニューがなくなるので、先に押す）
2. リポジトリのルートで、本体のコードをテスト用スクリプトに戻す。中身と権限の設定が丸ごと置き換わる

   ```sh
   npm run push:test
   ```

3. Apps Script のエディタの「デプロイ ▸ デプロイを管理」で、検証で作ったデプロイをアーカイブする
4. エディタの左の「トリガー」（時計の形）で、トリガーが残っていれば削除する
5. スプレッドシートの「T1-1 検証ログ」「T1-1 公開データ」タブを削除する
6. リリースを削除する

   ```sh
   gh release delete spike-t1-1 --repo yuk-wq/ouca --cleanup-tag --yes
   ```

## 開発者向けの補足

### 注意

- 「前のバージョンに戻す」の後に「記録を消す」を飛ばして「アプリを更新」を押すと、全段階が済みとして何もしない
- 「アプリを更新」を二重に押すと、バージョンが2つできる可能性がある（LockService を使っていない）
- 検証の操作は、`Session.getActiveUser().getEmail()` が空、または `getEffectiveUser()` と違うときは、何もせずに例外で止め、ログにも書かない。Web アプリは匿名で開けて持ち主の権限で動くので、`google.script.run` から呼ばれるのを防ぐため
- 時間主導のトリガーの入口（`publishMenuSpikeFromTrigger`）は、イベントの `triggerUid` がこのスクリプトのトリガーの ID と一致するときだけ動く。一致したかもログに書く
- バージョンの数の上限は 200 とされる。実際には作らず、「状態を見る」の「バージョンの数」を記録する

### シナリオと手順の対応

| # | Issue のシナリオ | 手順 | 判断に使うログ |
|---|---|---|---|
| 1 | 自分の中身を置き換えられる | 6 | 「更新 段階 2」が OK か。NG なら本文が理由 |
| 2 | バージョンとデプロイを作れる | 3、6 | 「初期の Web アプリを作る」（デプロイがないときの作成）、「更新 段階 3」のバージョン番号、「更新 段階 4」の update か create か、切り替え前後の URL |
| 3 | 実行中に置き換えても最後まで動く | 6 | 段階 2 の後の段階 3、4 が OK か。各行の「コード」の列が実行中のコード |
| 4 | 置き換えの後に新しい「メニューを公開」を呼べる | 6 | 「公開データ」の3行の動いたコード。同じ実行が A、トリガーと押し直しが B なら、別の実行が要る |
| 5 | リリースの添付ファイルを取れる | 4 | 「取得を試す」。各 URL の転送のたどり方と最終の状態コード |
| 6 | 持ち主として作ったものは持ち主として実行 | 8、編集者の確認 | Web アプリの `getEffectiveUser` |
| 7 | 既定の Cloud プロジェクトのままで API を呼べる | 2 | 最初の「状態を見る」が OK か。403 なら本文が理由 |
| 8 | 置き換えの直後、メニューは新しく Web アプリは古い | 5 | 「状態を見る」の HEAD のコード、押し直しの動いたコード、Web アプリの表示 |
| 9 | 各段階の後で止めても続きから進める | 7 | 1回目が「停止（意図）」、2回目に「段階 N は済み。飛ばす」 |
| 10 | 前のバージョンの中身を番号から取り出せる | 5、6、7 | 「前のバージョンに戻す」の取り出したバージョン番号とコード。手順 5 と 7 は途中で止まった後の取り出しになる |

### 権限の範囲（oauthScopes）

使う API から決め、`gas/appsscript.json` にだけ書く。テスト用スクリプトをエディタで直さない。

| 範囲 | 使う場所 |
|---|---|
| `spreadsheets` | ログのタブと公開データのタブへの書き込み |
| `script.container.ui` | メニューの追加（`onOpen`） |
| `script.external_request` | `UrlFetchApp`（GitHub と Apps Script API） |
| `script.projects` | `projects.updateContent`、`getContent`、`versions.create`、`versions.list` |
| `script.deployments` | `projects.deployments.list`、`create`、`update` |
| `script.scriptapp` | 1回だけの時間主導のトリガーの作成と削除。`ScriptApp.getOAuthToken()` |
| `userinfo.email` | `Session.getEffectiveUser().getEmail()`、`getActiveUser().getEmail()` |

### コード B のバンドルを作って公開する

```sh
node spikes/T1-1-self-update/make-bundle.mjs B
gh release create spike-t1-1 spikes/T1-1-self-update/out/ouca-bundle.json \
  --repo yuk-wq/ouca --title "T1-1 検証用" --notes "T1-1 の検証用。終わったら消す" --latest
```

- `--latest` は、`releases/latest/download/` の URL も確かめるために付ける
- コードを直したら、作り直して `gh release upload spike-t1-1 spikes/T1-1-self-update/out/ouca-bundle.json --repo yuk-wq/ouca --clobber` で差し替える。差し替えた直後の数十秒は、`latest` の URL から古い中身が返ることがある

### コード A をテスト用スクリプトに送る

```sh
npm run push:spike -- T1-1-self-update
```

`.clasp.test.json` の `scriptId` に送る。中身とマニフェストは丸ごと置き換わる。`.clasp.test.json` がないときは、作り方を表示して止まる。
