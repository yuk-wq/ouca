# T1-1 読み込み方式の検証

Issue #7。最初の方式（スクリプトが Apps Script API で自分の中身を置き換える）は、既定の Cloud プロジェクトで API を有効にできず成り立たなかった（`docs/to-be/spikes.md` の最初の方式のシナリオ 7）。この検証では、代わりの「読み込み方式」が GAS で成り立つかを確かめる。

読み込み方式では、スクリプト本体（ローダー）は最初のコピーのまま変えない。「アプリを更新」は、GitHub のリリースからコードを取り、スプレッドシートの非表示のタブ「_コード」に保存して、どのコードを使うかの印を切り替えるだけにする。メニュー、トリガー、画面の API、Web アプリは、実行のたびに保存したコードを読み込んで動かす。Web アプリの画面も、保存した HTML から出す。

保存するコードのうち、最初に入っているものを「コード A」、リリースから取ってくるものを「コード B」と呼ぶ。2つの違いは名前（と、コード B にだけある「範囲の外の操作」）だけで、どちらで動いたかがメニューの題名、ログ、Web アプリの画面に出る。

前半はデザイン担当が操作する手順、後半は開発者向けの補足になっている。

## 始める前に

メインのセッションから「ローダーを送った、リリースを差し替えた」と連絡があってから始める。連絡の前は、テスト用スクリプトの中身が前の検証のままだったり、リリースが古かったりして、結果を読み違える。

## 操作する場所

| 場所 | 開き方 | ここで見るもの、すること |
|---|---|---|
| テスト用スプレッドシート | Google ドライブから、デザイン担当が U-1（#6）で作った、テスト用スクリプトが紐づいたスプレッドシート（`.clasp.test.json` の scriptId のスクリプトが紐づいているもの）を開く | 操作の大半はここで行う |
| メニュー「T1-1 ローダー検証（コード A）」 | スプレッドシートの上のメニューで、「ヘルプ」の右にある | 検証の操作を押す。括弧の中が、今使っているコードが A か B か |
| 「T1-1 検証ログ」タブ | スプレッドシートの下のタブ。スプレッドシートを開いたときにできる | 押した操作の結果が1行ずつ増える。「結果」の列は OK、NG、停止（意図）のどれか。「コード」の列は、その行で動いたコード |
| 「T1-1 公開データ」タブ | 同じく下のタブ。「メニューの公開の代わり」が初めて動いたときにできる | 「動いたコード」の列で、A と B のどちらで動いたかを見る。「呼ばれ方」の列が、どこから動いたか |
| 「_コード」タブ | 非表示。通常は開かなくてよい。見るなら、下のタブの左端の「≡（すべてのシート）」から選ぶ | 保存したコードの置き場（開発者向けの補足に説明がある）。直さない |
| Web アプリのタブ | 手順 4 のデプロイで出る URL を、ブラウザの新しいタブで開く | 画面の下に黄色い帯が出て、コード A か B か、読み込み元、かかった時間が出る |
| Apps Script のエディタ | スプレッドシートの上のメニュー「拡張機能 ▸ Apps Script」 | 初回のデプロイと承認の確認だけに使う。コードは直さない |

## メニューの各項目がすること

| 項目 | すること |
|---|---|
| 初期設定（コード A を保存） | ローダーに同梱したコード A を「_コード」タブの枠 A に保存し、印を A にする。最初に1回だけ押す |
| アプリを更新 | GitHub のリリースのコードを取り、4つの段階で切り替える。1 取得と確認、2 使っていない枠への保存、3 印の切り替え、4 新しいコードでメニューの公開のやり直し |
| 前のバージョンに戻す | 印を前の枠に戻す。GitHub には触れない |
| メニューの公開の代わり（押し直し） | 保存したコードの「メニューを公開」の代わりの関数を呼び、「公開データ」タブに1行書く |
| トリガーで新しいコードが動くか（1分後） | 1分後に1回だけ動く時間主導のトリガーを作る。動いたとき、保存したコードの「メニューを公開」の代わりを呼ぶ |
| 読み込み時間を測る | 今のコードを、シートから、キャッシュから、の順に読み込み直し、それぞれの時間をログに書く |
| 範囲の外の操作を試す | 保存したコードの中の、マニフェストに書いていない権限の範囲（メール送信）を使う関数を呼び、どうなったかをログに書く。コード B だけが持つ |
| 取得を試す（固定の URL 2 つ） | GitHub のリリースのコード B をダウンロードできるかだけを試す。保存はしない |
| 止める設定 ▸ 段階 N の後で止める | 次に「アプリを更新」を押したとき、段階 N の後でわざとエラーで止める。1回止めると設定は消える |
| 止める設定 ▸ 止めない | 止める設定を取り消す |
| 止める設定 ▸ 各段階に 8 秒の待ちを入れる | 各段階の後に 8 秒待つ。「アプリを更新」を二重に押す確認のため |
| 止める設定 ▸ 待ちを入れない | 待ちの設定を取り消す |
| 取得先を切り替える（spike / latest） | 取ってくる URL を切り替える。通常は使わなくてよい |
| 状態を見る | 今の枠、前の枠、各枠のバージョンと大きさ、印、段階の記録、キャッシュの有無、待っているトリガーの数をログに書く |
| 記録を消す | 段階の記録、止める設定、待ちの設定、キャッシュ、トリガーを消す。保存したコードと印は残す |

## 手順

所要時間は 40〜60 分ほど。画面が手順と違ったら、その時点の画面の文言をメインのセッションに渡す。

### 1. 初回の承認

- 場所: テスト用スプレッドシート
- 操作
  1. スプレッドシートを開く。開いていたら、ブラウザで再読み込みする
  2. 数秒待ち、メニュー「T1-1 ローダー検証（未初期設定）」が出たことを確かめる。出なければもう一度再読み込みする。前の方式のメニュー「T1-1 検証（コード A）」が出る場合は、開発者が前の方式のコードを送ったままなので、メインのセッションに伝える
  3. 「初期設定（コード A を保存）」を押す
  4. 「承認が必要です」と出たら「OK」（または「続行」）を押す
  5. アカウントを選ぶ画面で、スプレッドシートの持ち主のアカウントを選ぶ
  6. 「このアプリは Google で確認されていません」と出たら、左下の「詳細」を押し、下に出る「（プロジェクト名）（安全ではないページ）に移動」を押す
  7. 権限の一覧が出たら、チェックボックスがあれば「すべて選択」を押し、「続行」（または「許可」）を押す。出た権限の一覧を控える（メール送信の権限が入っていないこと）
  8. スプレッドシートに戻り、もう一度「初期設定（コード A を保存）」を押す。承認した直後は、押した操作が動かないことがあるため
  9. スプレッドシートを再読み込みする。再読み込みの前は、メニューが2つ並ぶことがある。どちらを押してもよい
- 確かめること
  - 下のタブに「T1-1 検証ログ」ができ、「初期設定」が OK になっている
  - メニューの題名が「T1-1 ローダー検証（コード A）」になっている
  - 手順 9 の再読み込みで、メニューが保存したコードから出ている。ログに「onOpen（シンプルトリガー）」の行が増え、OK になっている（読み込み方式 1 のシンプルトリガー）

### 2. メニューから保存したコードを動かす

- 場所: テスト用スプレッドシート
- 操作
  1. 「メニューの公開の代わり（押し直し）」を押す
  2. 「読み込み時間を測る」を押す
  3. 「状態を見る」を押す
- 確かめること
  - 「T1-1 公開データ」タブができ、動いたコードが A、呼ばれ方が「メニューから押し直し」の行がある
  - 「読み込み時間を測る」のログに、シートから、キャッシュからの時間が出ている。数値をメインのセッションに渡す（読み込み方式 2）
  - 「状態を見る」のログで、枠 A に文字数が入り、キャッシュが「あり」になっている

### 3. リリースを取れるか試す

- 場所: テスト用スプレッドシート
- 操作
  1. 「取得を試す（固定の URL 2 つ）」を押す
- 確かめること
  - ログに行が増える。「[spike]」と「[latest]」の 2 行とも「JSON として読めた」と出ていれば、次へ進む。出ていない行があれば、その行の文言をメインのセッションに渡して止まる（読み込み方式 7）

### 4. 最初の Web アプリのデプロイを作る

Web アプリのデプロイは、スクリプトからは作れない（Apps Script API が使えない）ので、エディタで手で作る。本番ではオーナーの初回の手順になるので、押した項目と、出た画面の文言を控える。

- 場所: Apps Script のエディタ、Web アプリのタブ
- 操作
  1. スプレッドシートの上のメニュー「拡張機能 ▸ Apps Script」を押し、エディタを開く
  2. エディタの右上の青いボタン「デプロイ」を押し、「新しいデプロイ」を押す
  3. 「新しいデプロイ」の画面の左上、「種類の選択」の横の歯車のアイコンを押し、「ウェブアプリ」を押す
  4. 「説明」に「T1-1 ローダー」と入力する
  5. 「次のユーザーとして実行」を「自分（自分のメールアドレス）」にする
  6. 「アクセスできるユーザー」を「全員」にする
  7. 右下の「デプロイ」を押す
  8. 承認を求められたら「アクセスを承認」を押し、手順 1 と同じ要領で承認する
  9. 表示された画面の「ウェブアプリ」の下にある URL（`https://script.google.com/macros/s/…/exec`）をコピーし、「完了」を押す
  10. ブラウザの新しいタブで URL を開く。このタブは最後まで開いたままにする
  11. Web アプリの画面の下の黄色い帯の「画面の API を呼ぶ」を押す
  12. Web アプリのタブを再読み込みする
- 確かめること
  - Web アプリのタブに、保存した HTML の画面（OUCA の画面）と、下の黄色い帯が出る。帯に「コード A」と、読み込み元、かかった時間が出る（読み込み方式 1 の Web アプリ、読み込み方式 10）
  - 「画面の API を呼ぶ」を押すと、「返ってきたコード: A」と出る（読み込み方式 1 の画面の API）
  - 1 回目も 2 回目も、読み込み元はキャッシュかシートのどちらかになる。値を控える
  - 手順 3 から手順 9 のどこで、何と出たか（項目名、承認の文言）を控える。画面が上の説明と違った場所を、特に控える

### 5. 時間主導のトリガーで動くか

- 場所: テスト用スプレッドシート
- 操作
  1. 「トリガーで新しいコードが動くか（1分後）」を押す
  2. ログに「トリガーで保存したコードを呼ぶ」の行が出るまで待つ（数分かかることがある）。出ないときは、ときどきタブを見直す
- 確かめること
  - ログに「トリガーの確認」（OK、一致 true）と「トリガーで保存したコードを呼ぶ」（OK）の行がある
  - 「公開データ」タブに、呼ばれ方が「時間主導のトリガー」の行がある（読み込み方式 1 の時間主導のトリガー）

### 6. 最後まで更新する

- 場所: テスト用スプレッドシート、Web アプリのタブ
- 操作
  1. 「アプリを更新」を押す。エラーなく終わる
  2. Web アプリのタブを再読み込みする（URL は変えない）
  3. 「公開データ」タブを見る
  4. スプレッドシートを再読み込みする。再読み込みの前は、メニューが2つ並ぶことがある。どちらを押してもよい
  5. 「読み込み時間を測る」を押す
- 確かめること
  - 手順 1 のログに、段階 1〜4 の行が OK で並ぶ。段階 4 の行のコードの列が B で、「読み込み直したコードは B」と出ている（読み込み方式 3）
  - 「公開データ」タブに、動いたコードが B、呼ばれ方が「同じ実行から（段階 4）」の行がある（同じ実行の中で新しいコードの「メニューを公開」を呼べた）
  - 手順 2 の後、Web アプリのタブの帯が「コード B」になり、HTML の先頭の目印も新しくなっている。URL は変わっていない。デプロイは作り直していない（読み込み方式 4）
  - 手順 4 の後、メニューの題名が「コード B」になっている
  - 手順 5 の後、ログに B のコードの読み込み時間が出る（読み込み方式 2）
- 注意
  - 手順 1 の途中でメニューの題名が変わるかどうか（再読み込みの前に変わったか）を控える

### 7. 範囲の外の操作

- 場所: テスト用スプレッドシート
- 操作
  1. コード B のまま、「範囲の外の操作を試す」を押す
  2. 承認の画面が出たら、画面の文言を控え、承認するかどうかを「承認しない」で試す。出なければ何もしない
- 確かめること
  - ログに結果が出る。「例外になった」ならその文言（足りない権限の範囲の名前が入っているか）、「動いた」なら承認の扱いを控える（読み込み方式 9）

### 8. 途中で止まっても続きから進めるか

次の流れを、N を 1、2、3、4 に変えて4回繰り返す。

- 場所: テスト用スプレッドシート
- 操作
  1. 「前のバージョンに戻す」を押し、続けて「記録を消す」を押す（印が A の状態から始める。印が A のときは、戻す先がない旨が出るので、そのまま「記録を消す」を押す）
  2. 「止める設定 ▸ 段階 N の後で止める」を押す
  3. 「アプリを更新」を押す。エラーのダイアログが出るので「閉じる」を押す
  4. 「状態を見る」を押し、スプレッドシートを再読み込みする
  5. もう一度「アプリを更新」を押す。今度はエラーなく終わる
  6. 「状態を見る」を押す
- 確かめること
  - 手順 5 のログに、「段階 N は済み（日時）。飛ばす」と出ている（N までの各段階について）
  - N が 3 か 4 のとき、手順 4 の後でメニューの題名と Web アプリが B になっている。N が 1 か 2 のときは、A のまま（印を切り替える前なので）
  - 手順 6 のログで、印が B、前が A、段階の記録が「（なし）」になっている（最後まで済むと段階の記録が消える）

#### 二重に押しても 1 回しか進まないか

- 操作
  1. 「前のバージョンに戻す」「記録を消す」の順に押す
  2. 「止める設定 ▸ 各段階に 8 秒の待ちを入れる」を押す
  3. 「アプリを更新」を押し、すぐにもう一度「アプリを更新」を押す
  4. 両方が終わるまで待ち、「止める設定 ▸ 待ちを入れない」を押す
- 確かめること
  - この確認で増えた行の中で、「別の更新が動いているので、何もしなかった」が1回出ているか、2回目が全段階「済み（日時）。飛ばす」になっている。「更新 段階 1」から「更新 段階 4」の行が、それぞれ1行ずつしかない（読み込み方式 5）

### 9. 前のバージョンに戻す

- 場所: テスト用スプレッドシート、Web アプリのタブ
- 操作
  1. 手順 8 の最後で、更新が済んで印が B の状態にする
  2. 「前のバージョンに戻す」を押す
  3. Web アプリのタブを再読み込みする
  4. スプレッドシートを再読み込みする
  5. 更新が途中で止まった後でも戻せるかを、次の順で確かめる。「記録を消す」、「止める設定 ▸ 段階 3 の後で止める」、「アプリを更新」（エラーのダイアログを閉じる）、「前のバージョンに戻す」、Web アプリのタブの再読み込み
  6. 「記録を消す」を押す
- 確かめること
  - 手順 2 から手順 4 の後、メニューの題名も Web アプリも「コード A」に戻っている
  - 手順 5 の後も、メニューの題名と Web アプリが「コード A」に戻る（読み込み方式 6）

### 10. 別のアカウントで Web アプリを開く（任意）

- 場所: ブラウザのシークレットウィンドウ
- 操作
  1. シークレットウィンドウで、別の Google アカウントにログインする
  2. Web アプリの URL を開く
- 確かめること
  - 画面の帯の `getEffectiveUser` が、スプレッドシートの持ち主のメールアドレス（先頭2文字とドメインだけ）になっている（読み込み方式 8）

### 11. 大きいバンドルでの読み込み時間（任意）

メインのセッションがパディング付きのバンドルをリリースに上げたときだけ行う。

- 場所: テスト用スプレッドシート
- 操作
  1. 「記録を消す」、「アプリを更新」、「読み込み時間を測る」の順に押す
  2. Web アプリのタブを再読み込みし、帯に出る時間を控える
- 確かめること
  - 「読み込み時間を測る」のログの文字数と、シートから、キャッシュからの時間（読み込み方式 2。本番に近い大きさ）

### 12. 結果を渡す

- 場所: テスト用スプレッドシート、メインのセッションとのチャット
- 操作
  1. 「T1-1 検証ログ」タブを開き、左上の角（A と 1 の間の四角）を押して全体を選び、コピーしてチャットに貼る
  2. 「T1-1 公開データ」タブも同じようにして貼る
  3. 手順 1、4、7、10 で控えたこと（承認の権限の一覧、デプロイで押した項目と出た文言、承認の画面の文言、Web アプリの表示）をチャットに書く
- 補足
  - チャットには URL やメールアドレスをそのまま貼ってよい。リポジトリは公開なので、`docs/to-be/spikes.md` に書くときは、メインのセッションが Web アプリの URL、デプロイ ID、メールアドレスを伏せる

片付けは、メインのセッションが結果を確かめた後に行う（下の「片付け」）。

## 片付け

メインのセッションが結果を確かめた後に行う。

1. テスト用スプレッドシートで「前のバージョンに戻す」「記録を消す」の順に押す（次の手順の後はメニューがなくなるので、先に押す）
2. リポジトリのルートで、本体のコードをテスト用スクリプトに戻す。中身と権限の設定が丸ごと置き換わる

   ```sh
   npm run push:test
   ```

3. Apps Script のエディタの「デプロイ ▸ デプロイを管理」で、検証で作ったデプロイをアーカイブする
4. エディタの左の「トリガー」（時計の形）で、トリガーが残っていれば削除する
5. スプレッドシートの「T1-1 検証ログ」「T1-1 公開データ」「_コード」タブを削除する（「_コード」は非表示なので、先に「すべてのシート」から表示する）
6. スクリプトのプロパティ（`T11L_*`）は、中身を置き換えたスクリプトでは使われないので、残ってよい
7. リリースを削除する

   ```sh
   gh release delete spike-t1-1 --repo yuk-wq/ouca --cleanup-tag --yes
   ```

## 開発者向けの補足

### 保存先と印

| もの | 場所 | 中身 |
|---|---|---|
| 枠 A、枠 B | 非表示のタブ「_コード」の 1 列目、2 列目 | 1 行目 id（バージョンと保存時刻）、2 行目 文字数、3 行目から本文を 4 万字ずつ（セルの上限は 5 万字） |
| 取得済みの置き場 | 同じタブの 3 列目 | 段階 1 で取った本文。段階 2 が、使っていない枠にコピーする |
| 印 | スクリプトのプロパティ `T11L_MARK` | `{"cur":{枠,id},"prev":{枠,id}または null}`。切り替えは 1 回の書き込み |
| 段階の記録 | `T11L_STATE` | 済んだ段階と、書き込む枠 |
| 止める設定、待ち、取得先 | `T11L_STOP_AFTER`、`T11L_SLOW`、`T11L_URL_KEY` | |
| キャッシュ | スクリプトのキャッシュ（6 時間） | 鍵は枠と id。値は 3 万字ずつに分ける（1 つの値の上限は 100KB で、日本語は 1 字 3 バイトまで） |

- 枠 A、B のうち、印が指さない方に次のコードを書く。書き込み中に止まっても、今のコードは壊れない
- 枠の id が印の id と合わないときは、読み込みを止める

### 注意

- 段階の記録は、更新が最後の段階まで済んだとき、と「前のバージョンに戻す」を押したときに自動で消える。途中で止まったままの記録は残り、次の「アプリを更新」が続きから進む。止まった後に戻さず、別のバージョンの更新を始めたいときは、先に「記録を消す」を押す
- 更新が段階 2 までで止まった後に「前のバージョンに戻す」を押すと、印がまだ切り替わっていないので、戻す先がない旨が出て、印は今のコードのままになる。このとき段階の記録は消えない
- 前の方式のスクリプトのプロパティ `T11_*` は使わない。残っていても動く。「記録を消す」で消える
- 検証の操作は、`Session.getActiveUser().getEmail()` が空、または `getEffectiveUser()` と違うときは、何もせずに例外で止める。Web アプリは匿名で開けて持ち主の権限で動くので、`google.script.run` からメニューの関数を呼ばれるのを防ぐため。ただし `getCatalogSpike` は画面の API の代わりなので、守りを付けず、コードの区別だけを返す
- シンプルトリガー（`onOpen`）は、本物のシートのオブジェクトを持つイベントのときだけ動く。時間主導のトリガーの入口（`runCodeFromTrigger`）は、イベントの `triggerUid` がこのスクリプトのトリガーの ID と一致するときだけ動く
- ローダーの一番外側の関数は固定の一覧（`onOpen`、`doGet`、`menu*`、`getCatalogSpike`、`runCodeFromTrigger`）だけ。保存したコードの関数は `new Function` の中にあり、一番外側に出ないので、`google.script.run` や Web アプリからは名前で呼べない。外から届くのは、ローダーの固定の一覧が呼ぶものだけ
- Web アプリの `doGet` は、匿名で開けるので、失敗しても理由を画面に出さない。メールアドレスは先頭 2 文字とドメインだけを出す

### シナリオと手順の対応

| # | 確かめること | 手順 | 判断に使うもの |
|---|---|---|---|
| 1 | 保存したコードを、メニュー、シンプルトリガー、Web アプリ、画面の API、時間主導のトリガーから動かせる | 1、2、4、5 | 公開データの呼ばれ方、ログの onOpen の行、Web アプリの帯と画面の API の表示 |
| 2 | 読み込みの時間（シートから、キャッシュから。本番に近い大きさ） | 2、6、11 | 「読み込み時間を測る」のログ |
| 3 | 「アプリを更新」で切り替わり、同じ実行の中で新しいコードのメニューの公開を呼べる | 6 | 段階 4 の行、公開データの「同じ実行から（段階 4）」 |
| 4 | 切り替えの直後、Web アプリを再読み込みすると新しい HTML とコードになる。URL とデプロイは変わらない | 6 | Web アプリの帯、URL の比較 |
| 5 | 各段階の後で止めても続きから進む。二重に押しても1回しか進まない | 8 | 「段階 N は済み。飛ばす」、ログの段階の行の数 |

### 権限の範囲（oauthScopes）

ローダーと保存したコードの両方が使う範囲を、最初から `gas/appsscript.json` にすべて書く。保存したコードでマニフェストは変えられないので、後から足せない。Apps Script API の範囲（`script.projects`、`script.deployments`）は要らない。

| 範囲 | 使う場所 |
|---|---|
| `spreadsheets` | ログ、公開データ、「_コード」タブの読み書き |
| `script.container.ui` | メニューの追加 |
| `script.external_request` | `UrlFetchApp`（GitHub） |
| `script.scriptapp` | 1回だけの時間主導のトリガーの作成と削除 |
| `userinfo.email` | `Session.getEffectiveUser().getEmail()`、`getActiveUser().getEmail()` |

### コード A をローダーに同梱した理由

最初のコード A は `gas/InitialBundle.js` に入れて、ローダーと一緒に送る。初回の「初期設定」を、ネットワークと GitHub のリリースに頼らずに行えるため。リリースから取る方式にすると、最初の1回が GitHub の状態に左右される。コード A は `make-bundle.mjs A` が作り、手で直さない。作り直したら `npx prettier --write spikes/T1-1-loader` で整形する。

### バンドルを作って公開する

```sh
npm run build
node spikes/T1-1-loader/make-bundle.mjs A   # gas/InitialBundle.js と out/ouca-bundle-A.json
node spikes/T1-1-loader/make-bundle.mjs B   # out/ouca-bundle.json
npx prettier --write spikes/T1-1-loader
gh release create spike-t1-1 spikes/T1-1-loader/out/ouca-bundle.json \
  --repo yuk-wq/ouca --title "T1-1 検証用" --notes "T1-1 の検証用。終わったら消す" --latest
```

- コード A を作り直したら、ローダーを送り直す。HTML は `dist/index.html` の中身をそのまま使い、先頭に目印のコメント（`<!-- T1-1 コード X -->`）を足す
- 大きいバンドルを試すときは、`node spikes/T1-1-loader/make-bundle.mjs B 0.0.0-spike-B --pad=300` で HTML に 300KB のコメントを足し、`gh release upload spike-t1-1 spikes/T1-1-loader/out/ouca-bundle.json --repo yuk-wq/ouca --clobber` で差し替える。差し替えた直後の数十秒は、`latest` の URL から古い中身が返ることがある

### ローダーをテスト用スクリプトに送る

```sh
npm run push:spike -- T1-1-loader
```

`.clasp.test.json` の `scriptId` に送る。中身とマニフェストは丸ごと置き換わる。`out/` と `code-module.js` と `make-bundle.mjs` は送られない（`gas/` だけが送られる）。
