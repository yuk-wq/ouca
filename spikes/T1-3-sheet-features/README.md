# T1-3 シートの機能の検証

Issue #9。オーナーが豆の表のプルダウンやシートのメニューで、迷わず入力、公開、集計できるという設計が GAS で成り立つかを確かめる。確かめるのは次のとおり。

- 複数選択のプルダウンを Apps Script から設定できるか。候補を足すと、数式（VSTACK）を参照するプルダウンに自動で出るか
- メニュー、画像のボタン、時間主導のトリガー、インストール型の編集トリガーから、末尾が `_` の関数と末尾が `_` でない関数を呼べるか
- シンプルトリガー `onEdit` が、手入力、貼り付け、行の挿入、行の削除のどれで動くか。インストール型の変更トリガー（onChange）の `changeType`
- `SpreadsheetApp.newCellImage()` に data URL（SVG と PNG）を渡して、セルに画像を出せるか
- スマホのスプレッドシートアプリで、メニュー、画像のボタン、チェックボックス（＋インストール型の編集トリガー）が動くか
- 持ち主の確かめ（`Session.getActiveUser()`、`Session.getEffectiveUser()`、`getOwner()` の比較）が、各入口で成り立つか
- イベントの `triggerUid` と、プロジェクトのトリガーの ID が一致するか
- Web アプリの画面から `google.script.run.onEdit` に偽のイベントを渡したとき、何が届くか
- 管理用の Web ページ（オーナーだけが開ける2つ目のデプロイ）が成り立つか。`doGet` のイベントの中身、2つのデプロイを見分けられるか、スマホのブラウザで開けるか

検証用のコードは、ローダーやバンドルの仕組みを使わず、ふつうの一番外側の関数で書いてある。確かめたいのは GAS が一番外側の関数をどう呼ぶかだけなので、そう書いてある。操作するのはデザイン担当で、別の Google アカウントを1つと、スマホを使う。

前半はデザイン担当が操作する手順、後半は開発者向けの補足になっている。検証コードの設計は `DESIGN.md` にある。判定の表（シナリオごとに、出得る結果と、設計をどう変えるか）もそこにある。

呼び方を決める。

- アカウント A: ふだん使っているアカウント。テスト用スプレッドシートの持ち主で、オーナーの役をする
- アカウント B: T1-2 で使った別の Google アカウント。「知らない人」の役をする。A とは Chrome のプロフィールを分けて操作する
- 「\_ あり」「\_ なし」: 関数の名前の末尾が `_` であるか。たとえば「メニューの `_` あり」は、末尾が `_` の関数をメニューに割り当てた項目

## ログとまとめの読み方

### ログ（「T1-3 検証ログ」タブ）

1つの事実ごとに1行増える。列は次の6つ。

| 列     | 中身                                                                                                                                                      |
| ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 日時   | 書いた時刻                                                                                                                                                |
| シナリオ | `S01` から `S18` の番号。空の行は、どのシナリオにも属さない（準備、区切りなど）                                                                         |
| 入口   | 動いた入口。メニュー、画像のボタン、編集トリガー、変更トリガー、時間主導、シンプルトリガー、Web アプリ（doGet）、Web アプリ（google.script.run）のどれか |
| 事実   | 見たことの種類を表す鍵。`called`（関数が呼ばれた）、`owner`（持ち主の確かめ）、`uid`（triggerUid の照合）、`user.…`（ユーザーが書いた控え）など       |
| 値     | 事実の値。まとめの計算に使う。メールアドレスは先頭2文字と `***@` とドメインに伏せる                                                                      |
| 詳細   | 人が読むための補足。まとめの計算には使わない                                                                                                              |

### まとめ（「T1-3 まとめ」タブ）

メニュー「まとめを作る」を押すと、ログの全部の行から、シナリオごとの判定が「T1-3 まとめ」タブに書かれる。列は、シナリオ、名前、判定、根拠、設計への影響、未確定の理由。

- 判定は、`DESIGN.md` §2 の表の判定の名前のどれか。どれにも当てはまらないときは「未確定」で、「未確定の理由」に、足りない事実か足りない控え（`user.…`）の名前が出る
- 「未確定の理由」に出た事実は、手順をやり直すか、メニュー「控えを書く」で足す。足したら、もう一度「まとめを作る」を押す
- 判定ごとに設計がどう変わるかは、`DESIGN.md` §2 の表の「設計への影響」を見る。まとめのタブの「設計への影響」の列にも、同じ文が出る
- ログに出ないこと（セルに見えたか、押した後の画面、スマホでの見え方、デプロイを開けたか）は、ユーザーがメニュー「控えを書く」で書く

## 始める前に

- メインのセッションから「検証コードを送った」と連絡があってから始める。連絡の前は、テスト用スクリプトの中身が前の検証のままで、結果を読み違える
- テスト用スプレッドシートに、T1-1、T1-2 のタブが残っていてもよい。この検証のタブは、名前の先頭に「T1-3」が付く。「T1-3」のないタブは、この検証では触らない
- 前の検証のメニュー（「OUCA」「T1-1 ローダー検証」など）が出る場合は、検証コードがまだ送られていないので、メインのセッションに伝える
- Apps Script のエディタの「トリガー」（左の時計のアイコン）に、前の検証のトリガー（`runDaily`、`runOnEdit` など）が残っていたら、右端の「⋮」から「トリガーを削除」で消す。コードが入れ替わった後は、動かずにエラーのメールが届くだけになる
- アカウント A の Chrome のプロフィールと、スマホのブラウザ（Safari、Chrome）で、ログインしているのがアカウント A だけであるかを確かめる。複数のアカウントでログインしていると、Web アプリが「現在、ファイルを開くことができません」などになることがある（T1-2 でも出た）。A 以外のアカウントがログインしていたら、ログアウトするか、「困ったとき」の対処に従う
- アカウント B でログインできる Chrome のプロフィールが、T1-2 のものとして残っているか確かめる。なければ、手順 7 の前に作る（T1-2 の README の手順 4 の操作 1 と 2）
- 手元に、小さなファイルを用意する。メモ帳で「dummy」とだけ書いた `dummy.txt` か、PC やスマホにある小さな画像など、個人情報のないものにする（手順 6 と 8 の form の送信で使う）
- スマホは、スプレッドシートのアプリ（iPhone でも Android でもよい）に、アカウント A でログインしておく
- ブラウザは PC では Chrome を使う。所要時間は 120〜180 分ほど（時間主導のトリガーを待つ時間を含む）。画面が手順と違ったら、その時点の画面の文言をメインのセッションに渡す
- 手順は、操作する場所ごとにまとめてある。順番どおりに進める。手順 4 で作るトリガーを、手順 5 のスマホの確認が終わるまで消さない

ほかに、検証用のコードが勝手に動くものがある。

- シンプルトリガー `onOpen`: スプレッドシートを開くたびにメニューを作り、ログに1行書く
- シンプルトリガー `onEdit`: 「T1-3 …」のタブを編集するとログに1行書く。ログとまとめのタブと、ほかのタブの編集は書かない
- 手順 4 で作ったトリガー: 「T1-3 …」のタブの編集と、時間が来たときにログに書く。チェックボックス（B6）を付けると、結果の欄（C6、D6）に時刻を書き、チェックを外す

## 手順

### 1. 準備を押し、承認する（PC、アカウント A）

- 場所: テスト用スプレッドシート（アカウント A）
- 操作
  1. スプレッドシートを開く。開いていたら、ブラウザで再読み込みする
  2. 数秒待ち、「ヘルプ」の右に、メニュー「T1-3 検証」が出たことを確かめる。出なければもう一度再読み込みする
  3. 「T1-3 検証 ▸ 準備（タブとダミーデータを作る）」を押す
  4. 「承認が必要です」と出たら「OK」（または「続行」）を押す。アカウントを選ぶ画面で、アカウント A を選ぶ
  5. 「このアプリは Google で確認されていません」と出たら、左下の「詳細」を押し、下に出る「（プロジェクト名）（安全ではないページ）に移動」を押す
  6. 権限の一覧が出たら、チェックボックスがあれば「すべて選択」を押し、「続行」（または「許可」）を押す。出た権限の一覧を控える
  7. スプレッドシートに戻り、もう一度「T1-3 検証 ▸ 準備」を押す。承認した直後は押した操作が動かないことがあるので、承認の後にもう一度押す
  8. 数秒待つ。画面の右下に「準備ができた」と出る
- 確かめること
  - 下のタブに、次のタブができている。「T1-3 検証ログ」「T1-3 豆の表」「T1-3 項目」「T1-3 \_リスト」「T1-3 管理」「T1-3 アイコン」
  - 「T1-3 \_リスト」の A 列に「果実」「ナッツ」「チョコレート」が縦に出ている（A1 の数式が、下の行に値を広げている）。数式のエラー（`#NAME?` や `#N/A`）が出ていたら、その表示を控える
  - 「T1-3 検証ログ」に、見出しの6列（日時、シナリオ、入口、事実、値、詳細）と、事実が `setup` の行がある
  - 承認の画面で出た権限の一覧を控えた。出なかった場合（前の検証で承認済み）は、出なかったことを控える

### 2. 複数選択のプルダウンと、候補の自動更新と、セルの画像（PC、アカウント A）

S01（複数選択）、S04（候補の自動更新）、S06（セルの画像）を確かめる。

- 場所: テスト用スプレッドシート（アカウント A）
- 操作

  13. 「デプロイ」を押し、「デプロイを管理」を押す。左の一覧に、2つのデプロイが出ることを確かめる。それぞれを押して、「アクセスできるユーザー」の欄が、1つ目は「全員」、2つ目は「自分のみ」のままかを控える。1つ目の設定が変わっていたら、変わった内容（文言）を控える。「閉じる」を押す。ここで一度止まる。チャットで「2つ目のデプロイを作った」とメインのセッションに伝え、返事を待つ（メインのセッションが、マニフェストが書き換わっていないかを確かめる）。返事の前に、操作 14 以降に進まない
  14. PC のテスト用スプレッドシートに戻り、「控えを書く」で問い 15（2つ目を作った後も、1つ目のデプロイのアクセスできるユーザーが「全員」のままか）に「はい」か「いいえ」を書く
  15. 新しいタブで、メモ帳の1つ目の URL の末尾に `?d=1` を付けて開く。2つ目の URL の末尾に `?d=2` を付けて、別のタブで開く
  16. 1つ目の画面で、次のことを確かめる。「1. doGet が受け取った情報」に、`d`、`keys`（e が持つ鍵）、`parameterKeys`、`getUrl`（ハッシュ付き）、`owner` が出ている。ブラウザの画面を、まるごと控える（スクリーンショットか、画面の文字のコピー）
  17. 「2. どこから開いたか」で「A の PC」を選び、「持ち主の確かめ（止めない版）を呼ぶ」を押す。「5. 結果」に、`passed` と `reason` が出る。続けて、「持ち主の確かめ（止める版）を呼ぶ」を押す。結果を控える
  18. 「値だけのオブジェクトを送る」を押す。結果を控える
  19. 「form（file 入力つき）を送る」を、ファイルを選ばずに押す。結果を控える。次に、「ファイルを選択」で、用意したファイルを選び、もう一度押す。結果を控える。続けて、「4b. e.source と e.range に別の値を入れた form を送る」の form で、「source」と「range」の両方の「ファイルを選択」に、小さな画像など個人情報のないファイル（用意したファイル）を選び、「form（source と range に file 入力）を送る」を押す。結果の `source`、`range` の欄（型とメソッド）と `real` の欄（false のままか）を控える。ファイルを選ばずに押した結果も控える
  20. 2つ目の画面（`?d=2`）でも、「2. どこから開いたか」で「A の PC」を選び、操作 17 と同じように、2つの確かめを押す。「1. doGet が受け取った情報」の `getUrl` の欄が、1つ目の画面の `getUrl` の欄と同じか違うかを控える
  21. メニュー「T1-3 検証 ▸ Web アプリの URL を調べる（伏せて記録）」を押す（スプレッドシートに戻って押す）。ログの最後の行に、エディタ側の `getUrl` の値が出る
- 確かめること
  - 1つ目のデプロイを作った後で、2つ目のデプロイを「自分のみ」で作れたか。1つ目の設定が変わらなかったか（S16（2つ目のデプロイ））
  - 持ち主のアカウント A のブラウザで、2つ目の URL も開けたか（S15（管理ページの持ち主の確かめ）、S16（2つ目のデプロイ））
  - 持ち主の確かめ（止めない版、止める版）が、アカウント A のブラウザで通ったか（S15（管理ページの持ち主の確かめ））。通らなかった場合の、`reason` の中身
  - `e` の鍵に何があるか（`parameter`、`pathInfo`、`contextPath`、`queryString` など）と、2つの画面で `getUrl` の欄が同じか違うか（S17（doGet のイベント））。同じなら、doGet は2つのデプロイを見分けられない
  - 偽のイベントを渡したときの結果（S13（偽のイベント））。値だけのオブジェクトと、2つの form（ファイルあり、なし）で、`e.range` と `e.source` がメソッドを持つか（`real`、`kind`、`source`、`range`、`shape` の欄）。source と range に file を入れた form で、`e.source` と `e.range` が `getBytes`、`getName` などの別のメソッドを持つ Blob になり、それでも `real` が false のままか

### 7. アカウント B のブラウザで開く（PC、アカウント B）

S11（知らない人の Web 呼び出し）、S15（管理ページの持ち主の確かめ）、S16（2つ目のデプロイ）を確かめる。アカウント B はスプレッドシートを開けないので、「控えを書く」は、手順 8 の後にアカウント A で行う。

- 場所: アカウント B の Chrome のウィンドウ
- 操作
  1. Chrome の右上のプロフィールのアイコンを押し、アカウント B のプロフィールを選ぶ。アカウント B でログインしていることを、Google のページ（`myaccount.google.com`）で確かめる

  3. 画面が開くことを確かめる。「2. どこから開いたか」で「B の PC」を選び、「持ち主の確かめ（止めない版）を呼ぶ」を押す。結果を控える。続けて、「持ち主の確かめ（止める版）を呼ぶ」を押す。「失敗」と出るか、成功と出るかを控える
  4. 「値だけのオブジェクトを送る」を押し、結果を控える
  5. 2つ目の URL の末尾に `?d=2` を付けて、同じウィンドウで開く。何が出るか（アクセスの拒否の画面か、ログインの画面か、ページが開くか）を、文言をそのまま控える。「アクセス権をリクエスト」などのボタンが出ても押さず、画面の文言だけを控える。ページが開いたら、「2. どこから開いたか」で「B の PC」を選び、2つの確かめを押す
- 確かめること
  - B のブラウザで、持ち主の確かめが止まるか。止まる場合は、`passed` が `false` か、「失敗」の文言か（S11（知らない人の Web 呼び出し））。`reason` が「active が空」か、「active と持ち主が違う」か
  - 2つ目のデプロイを、B で開けないか（S16（2つ目のデプロイ））

### 8. ログインしていないブラウザで開く（PC、シークレットウィンドウ）

- 場所: Chrome のシークレットウィンドウ

- 確かめること
  - ログインしていないブラウザから、1つ目の持ち主の確かめを呼ぶと、`active` が空になり、止まるか（S11（知らない人の Web 呼び出し））

### 9. スマホのブラウザで管理用のページを開く（スマホ、アカウント A）

S18（管理ページのスマホのブラウザ）を確かめる。スマホのブラウザは、iPhone なら Safari と Chrome の両方、Android なら Chrome だけで行う。

- 確かめること

### 作りと決めたこと

- ログは、列全体を「書式なしテキスト」にしてから書く。`=` で始まる値も数式にならない
- ログに書くメールアドレスと Web アプリの URL は、`log_` が書く前に伏せる。メールアドレスは先頭2文字、`***@`、ドメインに伏せる。一致の比較は、伏せる前の値（小文字にしたもの）で `ownerVerdict_` が行う
- `getUrl()` の値は、末尾の種類、ID の末尾4文字、全体のハッシュの先頭8文字だけを出す。2つのデプロイの `getUrl()` が同じかどうかは、ハッシュで比べる
- Web アプリの画面は、受け取った値を `textContent` で出す。サーバーが埋める値は、`<` `>` `&` と行の区切りをエスケープして `<script>` の中に置く
- 偽のイベントを受ける `onEdit` は、受け取った値の形をログに書いて返すだけで、シートの値を書き換えない
- Web アプリ（`google.script.run`）の中では `getActiveSpreadsheet()` が null になる可能性があるので、「準備」で保存したスプレッドシートの ID で開く
- トリガーの関数名は、`OWN_HANDLERS` の5つだけを作り、消す。ほかのトリガーは消さない
- 複数選択は、判定をユーザーの控え（`user.d2.script`、`user.d2.manual`、`user.d4`、`user.d3`）で決める。入力規則の JSON と、手でオンにする前後の JSON の差（`ms.diff`）は、根拠としてまとめに出す。複数選択が REST の JSON に出ない可能性があるためである
- 手でオンにする手順の画面の文言は、現在の画面と違う可能性がある。違ったときは、見つけた文言を控えてもらう

### 手元で確かめられないこと

次のことは、GAS の上と、実機でしか確かめられない。手元では、偽物の `SpreadsheetApp` などを使ったテスト（`npm test`）と、構文の確認（`node --check`）だけを行っている。

- GAS 上の動き（メニュー、トリガー、`google.script.run`、`insertImage`、`newCellImage` など）は、すべて手順 1 から 9 の実機の操作で確かめる
- 高度な Sheets サービスが、マニフェストに書いただけで使えるかは、手順 2 の `ms.d2.set` の行で分かる
- 複数選択をオンにする画面の文言（「複数選択を許可する」など）は、実際の画面と違う可能性がある
- 時間主導のトリガー（`after(60 * 1000)`）は、1分ちょうどに動くとは限らない（数分遅れる可能性がある）
- 末尾が `_` の関数を、メニュー、画像のボタン、トリガーから呼べるかは、実機でしか分からない。偽物のテストは、関数の名前の綴りが合っていることだけを確かめる
