# T1-3 シートの機能の検証の設計

Issue #9。メインのセッションが書く、検証コードの設計。実行役はこれに従って作る。ユーザーの操作の手順は `README.md` にある。

## 1. 考え方

- 検証の目的は、設計書（`docs/to-be/design.md` §2.14、§2.15、§3.3）の分かれ道を決めること。シナリオごとに、出得る結果と、それぞれで設計をどう変えるかを先に決めておく（§2 の判定の表）
- ログには、見たことを「事実」として1行ずつ書く。結論はログから計算する。メニューの「まとめを作る」が、事実の行からシナリオごとの判定を出し、「T1-3 まとめ」タブに書く。ユーザーが画面を見て判断する部分を減らし、読み違えを防ぐ
- 判定、照合、伏せ方、入力規則の JSON の読み方は、GAS を呼ばない純粋な関数（`gas/Logic.js`）にし、Vitest で確かめる。GAS を呼ぶ部分は薄くし、偽物の `SpreadsheetApp` などを置いて Vitest で確かめる
- 入口の守り（持ち主の確かめ、本物のシートのオブジェクトか、`triggerUid` の照合）は、設計書 §3.3 の決まりのとおりに `Logic.js` に書く。検証は、この関数が実機の値で期待どおりに判定するかも確かめる。結果が良ければ、T1-3 の後半でローダーに移す元になる
- テストを先に書く（`CLAUDE.md` の「テスト駆動」）。`spikes/` のコードは対象外とされているが、このタスクでは、レビューで見つかった誤り（チェックボックスの状態、入力規則の読み取り、偽のイベントの名前）がどれもテストで防げたので、テストを先に書く

## 2. 判定の表

控えとログが食い違うときは、判定を出さずに未確定とし、食い違いを理由に出す。例: `user.d2.script` がはいなのに、ビルダーの複数選択のメソッドを呼んでいない（`ms.builder` が none）。`ms.d5` が skipped（作り直しをしていない）なのに `user.d5` の答えがある。

同じ区切りの名前のまとまりが2つ以上あるとき（ユーザーがやり直したとき）は、最後のまとまりを使う。

未確定の理由が「止まった」「判定しない」など、結果が出たうえでの未確定のときは、手順をやり直さずにそのまま貼る（README に書く）。

## 3. ログとまとめの形

### 3.1 ログ（「T1-3 検証ログ」）

- 入口は決めた値の一覧から選ぶ: メニュー、画像のボタン、編集トリガー、変更トリガー、時間主導、シンプルトリガー、Web アプリ（doGet）、Web アプリ（google.script.run）

### 3.2 まとめ（「T1-3 まとめ」）

メニュー「まとめを作る」が、ログの全部の行を `summarize_(rows)` に渡し、返った表を書く。列は、シナリオ、名前、判定、根拠（使った行の数と要点）、設計への影響、未確定の理由。ユーザーはログとまとめの両方をチャットに貼る。

## 5. テストの一覧

置き場所は `spikes/T1-3-sheet-features/test/`。`gas/*.js` を `node:vm` で1つの文脈に読み込んで確かめる（`test/gas-globals.test.ts` と同じやり方）。Vitest の `include` と `tsconfig.tooling.json` の `include` に、このフォルダを足す。

### 5.1 純粋な関数（`logic.test.ts`）

- `maskEmail_`: ふつうのアドレス、空、`@` のない値
- `maskDigits_`: 5桁は残し、6桁以上は伏せる。URL の中の `project=123456789` を伏せる
- `ownerVerdict_`: 通る1件と、止まる4件（active が空、active と effective が違う、active と持ち主が違う、持ち主が空）。大文字と小文字の違いは同じとみなす（§3.3 のテストの一覧と同じ）
- `isRealSheetEvent_`
  - false になるもの: `undefined`、値だけのオブジェクト、`{ source: Blob の偽物, range: Blob の偽物 }`（`getName`、`getBytes`、`getContentType` を持ち、`getId` を持たない）、`getId` が別の ID を返すもの、`getId` が例外を投げるもの、`'edit'` で `range` がないもの
  - true になるもの: `'open'` で `range` がなく `source` が本物の偽物、`'edit'` で両方が本物の偽物
- `triggerMatch_`: 一致、一致しない、消えた後、uid なし。末尾4字と個数が付く
- `readValidation_`: `rowData` がない、`values` がない、`dataValidation` がない（どれも `none`）、ルールあり（`rule`）、エラー（`apiError`、数字が伏せてある）
- `diffPaths_`: 入れ子の鍵の違い、片方にだけある鍵、同じなら空
- `rangeCovers_`: `A1:A200`、`$A$1:$A$200`、`'T1-3 _リスト'!A1:A200` の形、範囲の外
- `classifyUrl_`: `/exec`、`/dev`、ほかの形。返り値に元の URL の ID が丸ごと入らない
- `decideCheckbox_`: B6 が true、B6 が false、ほかのセル、ほかのシート
- `summarize_`: §2 の表の判定ごとに少なくとも1件。行が足りないときに「未確定」と、足りない事実を出す
  - S01: ビルダーのメソッドを呼べても、`user.d2.script` がいいえなら「ビルダーで設定できる」にしない。`user.d4` がはいでも `ms.diff` が空なら「高度なサービスで設定できる」にしない。`user.d2.manual` がいいえなら、どの判定も出さず未確定にする
  - S02: `user.s02` がなければ、`menuUnderscore_` の行がなくても「呼べない」にしない
  - S03、S09: `_` ありの `trigger.created` がなければ「呼べない」にしない。作成がエラーなら「作れない」
  - S10: メニューか画像のボタンで止まったときと、トリガーだけで止まったときで、設計への影響の文が違う
  - S11: 止まった理由が「active と持ち主が違う」でも「止まる」
  - S16: `user.s16.*` の3つがそろわなければ未確定。どれかが期待と違えば「作れない」
  - S17: `e` の鍵の一覧が同じで、URL の引数に由来しない値のハッシュだけが違うときも「見分けられる」
  - S18: `d=2` でない行や、スマホでない行だけなら未確定
- 書く側とまとめの取り決め: 偽物の上でハンドラを動かし、書かれた行を `summarize_` に渡して、判定まで確かめる（S01 の D2 が null の場合、S04、S05、S06、S17）。事実の名前や値の形を書く側だけで変えると落ちる
- `safeJson_` に `</script>` を含む値を渡しても script が閉じない。`ehash` は `parameter`、`parameters`、`queryString` の違いでは変わらず、ほかの値の違いで変わる
- `Web` の画面の「どこから開いたか」の選択肢が、`Logic.js` の出どころの一覧と同じ（wiring）
- 番号の入力は、全角の数字と前後の空白も受け付ける（`normalize('NFKC')` の後に比べる）
- 判定の表との一致: `Logic.js` の判定のデータ（シナリオ、判定の名前、設計への影響）が、この DESIGN.md §2 の表と同じ（表を読んで比べる。表を直したらテストも落ちる）

### 5.2 GAS を呼ぶ部分（`handlers.test.ts`）

偽物は `test/fakes.ts` にまとめる（スプレッドシート、シート、範囲（値、入力規則、書式、メモ）、`Session`、`ScriptApp`（トリガーの作成、一覧、削除）、高度な Sheets サービス、`SpreadsheetApp.flush`）。呼ばれた順を記録できるようにする。

- チェックボックス: B6 を true にした編集で処理が動き、B6 が false に戻り、C6 と D6 に時刻と入口が書かれる。false にした編集と、ほかのセルの編集では何も書かない
- 入力規則の読み取り: 高度な Sheets サービスを呼ぶ前に `SpreadsheetApp.flush()` を呼ぶ。サービスが例外を投げたら、ログの値が `apiError` になり、数字が伏せてある
- 複数選択の設定: D2 にだけ入力規則を付け、D3:D6 の入力規則を消す
- 複数選択の確かめ: コピーの前に D3 を読み、コピーし、コピーの後に D3 を読む順になっている。D2 に入力規則がないときも JSON を読んでログに書き、トーストを出す
- 偽のイベント: `onEdit` に値だけのオブジェクトと form の偽物を渡すと、ログ以外のシートに書かない。返り値の JSON の `real` が false
- Web アプリの中: `getActiveSpreadsheet()` が null を返す偽物でも、画面から呼ぶ関数が、準備で保存した ID でスプレッドシートを開いてログに書く
- 控えを書く: 番号で選んだ問いの鍵で `user.〇〇` の行を書く。範囲外の番号と、決めた選択肢にない答えは書かずに知らせる。`=` で始まる文言も文字のまま書く
- トリガー: 作成は、この検証のトリガーを消してから決めた5つを作る。削除は、この検証の関数名のトリガーだけを消し、ほかを残す
- ログ: 値を書く前に、列の書式を書式なしテキストにする。メールアドレスと URL を、伏せずに書く道がない（`owner`、`doget` の行の値と詳細に、偽物の元のアドレスと URL が含まれない）

### 5.3 つながり（`wiring.test.ts`）

- メニューの `addItem`、`assignScript`、`newTrigger`、`Web.html` の `google.script.run.〇〇` に書いた関数名が、すべて一番外側の関数として存在する（綴りの誤りで手順が止まるのを防ぐ）
- 末尾 `_` でない一番外側の関数は、README の「入口の一覧」の表と同じ。末尾 `_` の入口（`menuUnderscore_`、`trigEdit_`、`timer_`、`buttonUnderscore_`）も、その表にある
- 一番外側に、関数でない値を出していない（設定の表などの定数を除く。除くものは一覧で決める）
