# T1-2 テンプレートのコピーの検証

Issue #8。オーナーがテンプレートの「コピーを作成」を押すだけで、スプレッドシートとスクリプトを自分の持ち物として手に入れられるかを確かめる。確かめるのは次のとおり。

- コピーしたスプレッドシートに、紐づいたスクリプトが複製され、コピーした人の持ち物になる
- コピー先に、保護、入力規則、条件付き書式、グラフ、画像のボタン、非表示で保護つきの「_コード」タブが残る
- コピー先のトリガーとスクリプトのプロパティが、コピーされるかどうか
- コピー先で、承認の後にメニュー「OUCA」が出る
- コピーした人が公開した Web アプリが、その人の権限で動く

この検証では、テンプレートの代わりに、テスト用スプレッドシートに「テンプレートの内容」を作る。作る処理も、コピー先で何が残ったかを調べる処理も、検証用のコードが行う。操作するのはデザイン担当で、別の Google アカウントを1つ使う。

前半はデザイン担当が操作する手順、後半は開発者向けの補足になっている。

呼び方を決める。

- アカウント A: ふだん使っているアカウント。テスト用スプレッドシートの持ち主で、テンプレートの持ち主にもなる
- アカウント B: 別の Google アカウント（個人の Gmail。メールを受け取れて、ログインできるもの）。オーナーの役をする。コピーを作り、Web アプリを公開する

## 始める前に

- メインのセッションから「検証コードを送った」と連絡があってから始める。連絡の前は、テスト用スクリプトの中身が前の検証のままで、結果を読み違える
- テスト用スプレッドシートに、T1-1 のタブ（「T1-1 検証ログ」「T1-1 公開データ」「_コード」）が残っていてもよい。「_コード」は、この検証で中身と保護を作り直す
- アカウント B を使えるようにしておく。B でログインできることを、先に確かめる
- ブラウザは Chrome を前提にする。B の操作は、A のログインと混ざらないように、Chrome のプロフィールを分けて行う（手順 4 で作る）
- 所要時間は 60〜90 分ほど。画面が手順と違ったら、その時点の画面の文言をメインのセッションに渡す

## 操作する場所

| 場所 | 開き方 | ここで見るもの、すること |
|---|---|---|
| テスト用スプレッドシート（アカウント A） | Google ドライブから、テスト用スクリプトが紐づいたスプレッドシート（`.clasp.test.json` の scriptId のスクリプトが紐づいているもの）を開く | テンプレートの役。「テンプレートを組み立てる」と、基準になる「コピー先を調べる」を押す |
| コピーしたスプレッドシート（アカウント B） | 手順 4 の「コピーを作成」の後に開く | オーナーの役。メニュー「OUCA」を押して、コピー先を調べる |
| メニュー「OUCA」 | スプレッドシートの上のメニューで、「ヘルプ」の右にある | 検証の操作を押す。初期設定の前は項目が2つ（初期設定、コピー先を調べる）、後は4つ |
| 「T1-2 検証ログ」タブ | スプレッドシートの下のタブ。操作を押すとできる | 押した操作の結果が増える。「項目」「期待」「実際」「結果」の列が、コピー先を調べた結果。「結果」は、残った、残らなかった、違う、取れなかった、参考のどれか |
| 「T1-2 テンプレートの内容」タブ | 同じく下のタブ。「テンプレートを組み立てる」でできる | テンプレートに作ったものの一覧。コピー先を調べるとき、これを「期待」として読む |
| 「T1-2 管理」タブ | 同じく下のタブ | 青い四角の画像が、画像のボタン。押すと「コピー先を調べる」が動く |
| 「_コード」タブ | 非表示。見るなら、下のタブの左端の「≡（すべてのシート）」から選ぶ | 保存したコードの置き場。直さない |
| Apps Script のエディタ | スプレッドシートの上のメニュー「拡張機能 ▸ Apps Script」 | スクリプトが複製されたことの確認、Web アプリの公開、トリガーの確認に使う。コードは直さない |
| Web アプリのタブ | 手順 9 のデプロイで出る URL を開く | 画面の右下に黄色い帯が出る |

## メニューの各項目がすること

| 項目 | すること |
|---|---|
| 初期設定 | 印が `_コード` の id と一致していれば、印を作り直さない。印がなく、`_コード` が読めれば、その id から印を作り直す。読めなければ（`_コード` がない、空、T1-1 の形のまま）、同梱の初期のコードを `_コード` に書き直して印を作る。`_コード` の既存の保護は残し、保護がなければ作る。時間主導（毎日）のトリガーを、なければ作る。メニューを作り直す。何度押しても同じ結果になる |
| テンプレートを組み立てる | テスト用スプレッドシートに、保護、入力規則、条件付き書式、グラフ、画像のボタン、非表示で保護つきの `_コード`、トリガー、スクリプトのプロパティ、「T1-2 テンプレートの内容」を作る。`_コード` は、保護と中身を作り直す（同梱の初期のコードで書き直し、印も更新する）。何度押しても同じ結果になる。アカウント A でだけ押す |
| コピー先を調べる | 作ったものが、いまのスプレッドシートに残っているかを1つずつ調べ、「T1-2 検証ログ」に1項目1行で書く。初期設定の前でも動く |
| 状態を見る | 印、スクリプトのプロパティの鍵、トリガーの数と種類、タブの一覧（非表示か）をログに書く |

## 手順

### 1. アカウント A で初期設定を押し、承認する

- 場所: テスト用スプレッドシート（アカウント A）
- 操作
  1. スプレッドシートを開く。開いていたら、ブラウザで再読み込みする
  2. 数秒待ち、メニュー「OUCA」が出たことを確かめる。項目は「初期設定」と「コピー先を調べる」の2つ。出なければもう一度再読み込みする。「T1-1 ローダー検証」などの別のメニューが出る場合は、開発者が前の検証のコードを送ったままなので、メインのセッションに伝える
  3. 「OUCA ▸ 初期設定」を押す
  4. 「承認が必要です」と出たら「OK」（または「続行」）を押す。出なければ、操作 9 に進む（T1-1 で承認済みで、権限が同じなので、承認の画面が出ないことがある）
  5. アカウントを選ぶ画面で、アカウント A を選ぶ
  6. 「このアプリは Google で確認されていません」と出たら、左下の「詳細」を押し、下に出る「（プロジェクト名）（安全ではないページ）に移動」を押す
  7. 権限の一覧が出たら、チェックボックスがあれば「すべて選択」を押し、「続行」（または「許可」）を押す。出た権限の一覧を控える
  8. スプレッドシートに戻り、もう一度「OUCA ▸ 初期設定」を押す。承認した直後は押した操作が動かないことがあるので、承認の後にもう一度押す
  9. 数秒待ち、スプレッドシートを再読み込みする。再読み込みの前は、メニューが2つ並ぶことがある。どちらを押してもよい
- 確かめること
  - 下のタブに「T1-2 検証ログ」ができ、「初期設定」の行の結果が OK になっている
  - 再読み込みの後、メニュー「OUCA」の項目が4つ（初期設定、テンプレートを組み立てる、コピー先を調べる、状態を見る）になっている
  - ログに「onOpen（シンプルトリガー）」の行が増え、詳細が「保存したコードのメニュー」になっている

### 2. アカウント A でテンプレートを組み立て、基準を取る

- 場所: テスト用スプレッドシート（アカウント A）
- 操作
  1. 「OUCA ▸ テンプレートを組み立てる」を押す。数十秒かかることがある。画面の右下に「完了」と出るまで待つ
  2. 「T1-2 検証ログ」の最後の行を読む。詳細に9項目（保護（シート全体）、保護（範囲）、入力規則、条件付き書式とグラフ、画像のボタン、`_コード` タブ、トリガー、スクリプトのプロパティ、テンプレートの内容タブ）が並び、すべて「OK」になっている
  3. 下のタブに、次のタブができたことを確かめる。「T1-2 保護シート」「T1-2 保護範囲」「T1-2 入力規則」「T1-2 リスト」「T1-2 書式とグラフ」「T1-2 管理」「T1-2 テンプレートの内容」
  4. 「T1-2 管理」タブを開き、青い四角の画像があることを確かめる。「T1-2 書式とグラフ」タブに、縦棒グラフがあることを確かめる
  5. 「T1-2 テンプレートの内容」タブを開き、行が並んでいることを確かめる（「期待の数」と「特徴」の列）
  6. 「OUCA ▸ コピー先を調べる」を押す。これが基準になる
  7. 「T1-2 検証ログ」タブで、左上の角（A と 1 の間の四角）を押して全体を選び、コピーしてチャットに貼る
  8. 貼り終えたら、「T1-2 検証ログ」タブを削除する（タブ名を右クリックして「削除」）。このタブもコピーされるので、消さないと、コピー先のログにこの基準の行が混ざる
- 確かめること
  - 操作 2 の9項目に「失敗（…）」があれば、その文言をチャットに貼り、メインのセッションの返事を待つ（この検証コードの API の使い方が合っていない可能性がある）
  - 操作 6 のログで、「結果」が「残った」になっている。「参考」が数行あってよい。「取れなかった（…）」は、その行の文言を控える（確かめられない API の行）

### 3. アカウント A でアカウント B に閲覧者として共有する

本番では、オーナーに「コピーを作成」のリンクを LINE で送る（`docs/to-be/delivery-flow.md` §4.1）ので、一般的なアクセスが「リンクを知っている全員（閲覧者）」になる可能性がある。この検証では、テスト用スプレッドシートを広く公開しないために、一般的なアクセスを「制限付き」のままにし、アカウント B を閲覧者に追加する。閲覧者としてコピーを作る点は、本番と同じ状況になる。本番の共有のしかたは T6-2 で決める。

- 場所: テスト用スプレッドシート（アカウント A）
- 操作
  1. スプレッドシートの右上の「共有」を押す
  2. 入力欄にアカウント B のメールアドレスを入れ、権限を「閲覧者」にする。「通知」はオンでもオフでもよい
  3. 「送信」（または「共有」）を押す
  4. 「共有」の画面の下の「一般的なアクセス」が「制限付き」のままであることを確かめる
  5. 共有の画面の歯車のアイコンを押し、「閲覧者と閲覧者（コメント可）にダウンロード、印刷、コピーの権限を付与する」がオンであることを確かめる（オンでないと、閲覧者がコピーを作れない）。画面の文言が違えば、その文言を控える
  6. ブラウザのアドレスバーの URL を選んで、コピーする。末尾の `/edit` から後ろ（`/edit#gid=…` など）を消し、代わりに `/copy` を付ける。これを、アカウント B のブラウザに自分で渡す（メモ帳に貼って手元に置くか、自分宛てのメッセージに貼る）。このリンクはチャットに貼らなくてよい
- 確かめること
  - 共有の画面に、アカウント B が「閲覧者」で出ている

### 4. アカウント B で「コピーを作成」を押す

- 場所: 新しい Chrome のウィンドウ（アカウント B 専用のプロフィール）
- 操作
  1. Chrome の右上のプロフィールのアイコンを押し、「追加」（または「新しいプロフィールを追加」）を押す。「ログインせずに続行」（または「アカウントなしで続行」）を押す。新しいウィンドウが開く。以降、アカウント B の操作は、このウィンドウだけで行う
  2. このウィンドウで、アカウント B に Google ログインする。ログインの画面が分からなければ、ブラウザのアドレスバーに `accounts.google.com` を入れて開く
  3. 手順 3 で用意した `/copy` のリンクを、このウィンドウで開く
  4. 「コピーを作成」の画面が出る。画面に出ている文言と、チェックボックス（「同じユーザーと共有する」「コメントと提案をコピーする」など）の初期の状態を控える。何も変えない。コピーの名前もそのままにする
  5. 青い「コピーを作成」ボタンを押す
- 確かめること
  - コピーしたスプレッドシートが開く。左上のファイル名が「（元の名前）のコピー」になっている
  - コピーを作成するまでに押した項目と、出た画面の文言を控える。承認の画面など、手順にない画面が出たら、その文言も控える

### 5. アカウント B で、開いた直後にメニュー「OUCA」が出るかを見る

- 場所: コピーしたスプレッドシート（アカウント B）
- 操作
  1. コピーを開いて数秒待ち、スプレッドシートの上のメニューを見る。「ヘルプ」の右に「OUCA」が出るかを控える
  2. 出なければ、ブラウザで再読み込みする。出るまでにした操作（再読み込みの回数など）を控える
  3. 「OUCA」を押し、出た項目を控える。ここでは項目を押さない
- 確かめること
  - メニュー「OUCA」が出る（シナリオ 3）
  - 項目が、2つ（初期設定、コピー先を調べる。最小のメニュー）か、4つ（初期設定、テンプレートを組み立てる、コピー先を調べる、状態を見る。保存したコードのメニュー）のどちらかを控える。2つなら、印がコピーされていない
  - 下のタブに、「T1-2 検証ログ」や「_コード」（非表示）などがあるかを控える。「T1-2 テンプレートの内容」「T1-2 管理」などのタブがコピーされている

### 6. アカウント B で、初期設定の前にコピー先を調べる

- 場所: コピーしたスプレッドシート（アカウント B）
- 操作
  1. 「OUCA ▸ コピー先を調べる」を押す
  2. 「承認が必要です」と出たら、手順 1 の操作 4 から 7 と同じ要領で承認する。アカウントはアカウント B を選ぶ。出た画面の文言（承認の画面、「このアプリは Google で確認されていません」の画面、権限の一覧）と、押した項目を控える
  3. 承認の後、もう一度「OUCA ▸ コピー先を調べる」を押す。承認した直後は押した操作が動かないことがあるので、承認の後にもう一度押す
  4. 数秒待つ。「T1-2 検証ログ」タブを開き、左上の角（A と 1 の間の四角）を押して全体を選び、コピーしてチャットに貼る
- 確かめること
  - ログの最後の行が「コピー先を調べる」の OK で、詳細に、残った、残らなかった、違う、取れなかったの数が出ている。「コピー先を調べる 開始」の行の詳細で、「テンプレート自身か=false」になっている
  - 「持ち主の確かめ（入口の守り）」の結果が「残った」になっている。「持ち主の確かめで止めた（…）」というエラーのダイアログが出たときは、その文言を控える
  - 結果が「残らなかった」と「違う」の行を控える。これがこのタスクの結果になる。ただし、次の行は想定内で、失敗ではない
    - 「スプレッドシートの持ち主」「実行する人」「編集者の一覧」「閲覧者の一覧」: 「残らなかった」が期待どおり（テンプレートの持ち主がコピー先に残らない）
    - 「保護の編集者に、テンプレートの持ち主を含むか」: 「残らなかった」が期待どおり。「違う」なら、テンプレートの持ち主が保護の編集者に残っている
    - 「保護の編集者の人数」: 「参考」。コピーで変わってよい
    - 「トリガー」: 「残らなかった」（数 0）が想定。トリガーはコピーされない
    - 「スクリプトのプロパティ」の3行: 「残らなかった」でも失敗ではない。コピーされないなら、初期設定が印を作り直す
  - 上の想定内の行以外で「残らなかった」「違う」「取れなかった」の行があれば、その行が、コピーで残らなかったものになる

### 7. アカウント B で、スクリプトが複製されていることを確かめる

- 場所: Apps Script のエディタ（アカウント B）、Apps Script のホーム
- 操作
  1. コピーしたスプレッドシートの上のメニュー「拡張機能 ▸ Apps Script」を押し、エディタを開く
  2. 左の「エディタ」（`<>` の形のアイコン）を押し、ファイルの一覧を見る。`Loader` と `InitialBundle` があることを確かめる。コードは直さない
  3. 左の歯車のアイコン「プロジェクトの設定」を押す。「スクリプト ID」と、Google Cloud Platform（GCP）プロジェクトの欄に何が出ているかを控える（ID はチャットに貼らなくてよい）
  4. 左の「トリガー」（時計の形のアイコン）を押す。トリガーが何も出ていないことを確かめる
  5. 新しいタブで `script.google.com/home` を開き、左の「マイプロジェクト」を押す。この検証のスクリプトが、一覧に出ることを確かめる。「所有者」（または「オーナー」）の列に何が出ているかを控える
- 確かめること
  - コピーしたスプレッドシートに、`Loader` などのファイルが入ったスクリプトが紐づいている（シナリオ 1）
  - 「マイプロジェクト」に、アカウント B のスクリプトとして出る。所有者がアカウント B になっている（シナリオ 2）
  - 「トリガー」に、トリガーが何もない（シナリオ 7）

### 8. アカウント B で初期設定を押し、メニューを確かめる

- 場所: コピーしたスプレッドシート（アカウント B）
- 操作
  1. 「OUCA ▸ 初期設定」を押す。手順 6 で承認済みなので、承認の画面は出ないはず。出たら、文言を控え、承認して、もう一度押す。「承認の後にもう一度押す」が要ったかを控える
  2. 「T1-2 検証ログ」タブで、「初期設定」の行の詳細を読み、控える。印の道は、次の3つのどれか
     - 「道: スクリプトのプロパティがコピーされ、印が一致した」: 印がコピーされていて、`_コード` の id と一致したので、作り直さなかった
     - 「道: 保存済みのバンドル」: 印がコピーされず、コピーされた `_コード` の id から印を作り直した
     - 「道: 同梱のコード」: `_コード` が使えず、同梱の初期のコードを保存して印を作った。理由も同じ行に出る
  3. ブラウザで再読み込みする。数秒待つ
  4. メニュー「OUCA」の項目が4つになっていることを確かめる。再読み込みの前は、メニューが2つ並ぶことがある
  5. 「OUCA ▸ 状態を見る」を押す
  6. 「OUCA ▸ コピー先を調べる」をもう一度押す
  7. 「T1-2 管理」タブを開き、青い四角の画像を押す。操作 6 と操作 7 で、「T1-2 検証ログ」に「コピー先を調べる 開始」の行が2つ増え、それぞれの下に調べた行が続くことを確かめる
  8. 「T1-2 検証ログ」タブの全体をコピーして、チャットに貼る
- 確かめること

### 保存先と印

| もの | 場所 | 中身 |
|---|---|---|
| 保存したコード（枠は1つ） | 非表示のタブ「_コード」の1列目 | 1行目 id（`T12@` と保存時刻と乱数）、2行目 文字数、3行目から本文を4万字ずつ（セルの上限は5万字） |
| 印 | スクリプトのプロパティ `T12_MARK` | `{"id":"…"}`。`_コード` の1行目の id と合わないときは、読み込みを止める |
| 確認用のプロパティ | `T12_SAMPLE` | ダミーの固定値。コピーされるかを調べるためだけに置く |
| テンプレートの内容 | 「T1-2 テンプレートの内容」タブ | 1行に、キー、項目、期待の数、特徴。最後に、テンプレートのスプレッドシートとスクリプトの ID、持ち主のメールアドレスのハッシュ（SHA-256。小文字にしたアドレスを16進にしたもの。シートにメールアドレスは書かない）、組み立てた日時（`meta.` で始まるキー）。コピー先を調べるとき、「期待」として読む |
| 検証ログ | 「T1-2 検証ログ」タブ | 1行が「日時、操作、項目、期待、実際、結果、詳細」の7列。書式を文字列にして書く（`=` で始まる値が数式にならない） |
| onOpen の経路 | スクリプトのキャッシュ（6時間） | シンプルトリガーが、ログを書けない場合に備えて残す |

- テンプレートの内容に入れる「特徴」は、作ったものを実際に読み直して書く。作る処理が書いた値ではない。コピー先の「実際」は、同じ読み取りの処理で取る
- 結果は、数と特徴の両方が同じなら「残った」、数が0なら「残らなかった」、それ以外は「違う」。API が例外を返したら「取れなかった（例外の文言）」
- 持ち主、編集者、閲覧者のメールアドレスは、先頭2文字とドメインだけをログに出す。テンプレートの持ち主との同一かどうかは、ハッシュで比べ、真偽で出す
- 「_コード」が T1-1 の形（id が `T12@` で始まらない）で残っているとき、初期設定は、中身を同梱の初期のコードで書き直す（既存の保護は残し、なければ作る）。「テンプレートを組み立てる」は、保護と中身を作り直し、ログに注意書きを出す

### 守り（`docs/to-be/design.md` §3.3）

- ローダーの一番外側の関数は固定の一覧だけ: `onOpen`、`doGet`、`menuInit`、`menuBuild`、`menuInspect`、`menuStatus`、`runDaily`、`runOnEdit`。保存したコードの関数は `new Function` の中にあり、一番外側に出ないので、`google.script.run` や Web アプリからは名前で呼べない。保存したコードは入口の関数の中でだけ評価し、`globalThis` に書き込まない
- 画像のボタンには、`menuInspect` を割り当てる
- オーナーの操作（`menu*`）は、先頭で持ち主の確かめを行う。`Session.getActiveUser().getEmail()` が空でなく、`Session.getEffectiveUser().getEmail()` とスプレッドシートの持ち主（`SpreadsheetApp.getActive().getOwner().getEmail()`）の両方と同じでなければ、何もせずに例外で止める。例外の文言には、確かめの結果の真偽だけを入れ、メールアドレスは入れない
- シンプルトリガー（`onOpen`）は、イベントの `source` が本物のシートのオブジェクト（`getId` が関数で、このスプレッドシートの ID と同じ）のときだけ動く
- 時間主導のトリガー（`runDaily`）は、イベントの `triggerUid` が `ScriptApp.getProjectTriggers()` の ID と一致するときだけ動く。インストール型の編集トリガー（`runOnEdit`）は、さらに本物のシートのオブジェクト（`e.range.getSheet` が関数）かも確かめる
- トリガーの中身は、`console.log` だけ。シートには書かない（編集のたびに行が増えないように）
- Web アプリの `doGet` は、匿名で開けるので、失敗しても理由を画面に出さない。メールアドレスは先頭2文字とドメインだけを出す

### 初期のコードをローダーに同梱した理由

初期のコード（`module-code.js`）は、`gas/InitialBundle.js` に入れて、ローダーと一緒に送る。印も `_コード` もないコピー先で、初期設定の前に「コピー先を調べる」を動かせる。`make-bundle.mjs` が作り、手で直さない。

```sh

npx prettier --write spikes/T1-2-template
```

### 手元で確かめられないこと

GAS の API の使い方の一部は、手元で確かめられない。推測で書いた箇所は、コードに `TODO(確認):` を付けている。

- `getDataValidation()` の `getCriteriaType()` と `getCriteriaValues()` の表記
- `ConditionalFormatRule.getBooleanCondition()` と、その `getCriteriaType()` の表記
- `OverGridImage.getScript()` の戻り値と、`insertImage`、`assignScript` の使い方
- `Protection.removeEditors` に `User` の配列を渡せること、コピー先の `getEditors()` の戻り値（`canDomainEdit()` と `setDomainEdit()` は失敗しても続け、ログの文言に残す）
- インストール型の編集トリガーのイベントに `triggerUid` が入ること
- Web アプリ（`doGet`）の中で `SpreadsheetApp.getActive()` が使えること（黄色い帯の真偽2つに使う。使えなければ帯に「取れなかった（…）」と出る）

グラフの種類は、型定義（`google-apps-script.spreadsheet.d.ts`）で確かめた。`EmbeddedChart` には種類を返すメソッドがなく、`modify().getChartType()` で取る。

取れなかった API は、ログの結果が「取れなかった（例外の文言）」になり、検証全体は止まらない。テンプレートの内容に「取れなかった（…）」が書かれ、コピー先でも同じ文言なら、同じものとして比べる。片方だけなら、結果は「取れなかった」になる。
