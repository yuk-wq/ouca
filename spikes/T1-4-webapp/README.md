# T1-4 Web アプリの動作の検証

Issue #10。お客さんがスマホで注文画面を開き、メニューを見て、前回の名前やハートが残った状態で注文できるという設計が、GAS の配信の仕組みで成り立つかを確かめる。確かめるのは次のとおり。

- メニューの JSON を HTML に埋め込んで、画面が読めるか（`$&`、`</script>`、U+2028 を含む値で確かめる）
- Vite でビルドした 1 つの HTML の module の script が、GAS の iframe の中で動くか
- スマホで画面の幅が端末に合うか。HTML の中の `viewport` が効くか
- localStorage と IndexedDB の値が、再読み込みと、閉じて開き直した後に残るか（開き方ごと）
- `addMetaTag` と `setFaviconUrl` が使えるか。ホーム画面に追加したときのアイコンは何か
- `/exec` と `/dev`、アカウントごとに、実行する人（effective）が持ち主か、シートを読み書きできるか
- `google.script.run` の往復の時間（5KB、50KB、200KB）
- ログインの状態と開き方（複数のアカウント、LINE の中のブラウザなど）ごとに、画面が開けるか。開けないときに、お客さんへの案内が要るか

調べる画面は、本番と同じ作り方にしてある。Vite（Preact と `vite-plugin-singlefile`）でビルドした 1 つの HTML を、`doGet` が文字列として読み、目印の文字列をメニューの JSON に置き換えて `HtmlService.createHtmlOutput` で返す。画面は、開くと自分で調べ、結果を `google.script.run` でスプレッドシートのログに書く。画面を見て分かること（幅が合って見えたか、アイコン、開けなかったときの画面の文言）は、画面の「控えを書く」で送る。

前半はデザイン担当が操作する手順、後半は開発者向けの補足になっている。検証コードの設計は `DESIGN.md` にある。判定の表（シナリオごとに、出得る結果と、設計をどう変えるか）もそこにある。

呼び方を決める。

- アカウント A: ふだん使っているアカウント。テスト用スプレッドシートの持ち主で、オーナーの役をする
- アカウント B: T1-2 で使った別の Google アカウント。お客さんの役をする。A とは Chrome のプロフィールを分けて操作する
- 調べる画面: Web アプリの URL を開くと出る画面。「どこから開いたか」を選ぶ欄と、いくつかのボタンがある
- 開き方: 調べる画面の「どこから開いたか」で選ぶ 8 つ。PC の Chrome（A だけでログイン、A と B の両方でログイン、B だけでログイン、シークレットウィンドウ）、iPhone の Safari、iPhone の LINE の中のブラウザ、Android の Chrome、Android の LINE の中のブラウザ。持っていない端末の開き方は、まとめで「確かめていない」と出る
- 再読み込み: 同じタブで、ブラウザの再読み込みを押す（PC は F5、スマホは画面を下に引く）
- 開き直し: 調べる画面のタブ（LINE の中のブラウザなら、その画面）を閉じて、同じ URL をもう一度開く。スマホのブラウザは、画面を閉じるだけでなく、アプリのアイコンの一覧から上に払って終了させてから開き直す

## ログとまとめの読み方

### ログ（「T1-4 検証ログ」タブ）

1つの事実ごとに1行増える。列は次の6つ。

| 列       | 中身                                                                                                                                                               |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 日時     | 書いた時刻                                                                                                                                                         |
| シナリオ | `W1` から `W9` の番号。空の行は、どのシナリオにも属さない（開き方を選ぶ前の行など）                                                                               |
| 開き方   | 調べる画面で選んだ「どこから開いたか」。選ぶ前に送る行は空                                                                                                         |
| 事実     | 見たことの種類を表す鍵。`embed`、`module`、`classic`、`viewport`、`viewport.html`、`storage.local`、`storage.idb`、`meta`、`favicon`、`exec`、`rtt`、`user.…` など |
| 値       | 事実の値。まとめの計算に使う。メールアドレスと Web アプリの URL は伏せる                                                                                           |
| 詳細     | 人が読むための補足。保存の行では、`reload`（再読み込み）、`reopen`（開き直し）、`unknown`（見分けられない）が入る                                                  |

### まとめ（「T1-4 まとめ」タブ）

メニュー「まとめを作る」を押すと、ログの全部の行から、シナリオごとの判定が「T1-4 まとめ」タブに書かれる。列は、シナリオ、名前、判定、根拠、設計への影響、未確定の理由、表。

- 判定は、`DESIGN.md` §2 の表の判定の名前のどれか。どれにも当てはまらないときは「未確定」で、「未確定の理由」に、足りない事実か足りない控え（`user.…`）が出る
- 判定が「開き方ごとの表」「種類ごとの表」「入口ごとの表」「大きさごとの表」のものは、結果を「表」の列に JSON で書く。設計への影響は、結果を見て、メインのセッションが決める
- 保存の表（W4）の「見分けられない」は、sessionStorage が使えず、再読み込みと開き直しを見分けられなかった行がある。
- 「未確定の理由」に出た事実は、手順をやり直すか、調べる画面の「控えを書く」で足す。足したら、もう一度「まとめを作る」を押す

## 始める前に

- メインのセッションから「検証コードを送った」と連絡があってから始める。連絡の前は、テスト用スクリプトの中身が前の検証のままで、結果を読み違える
- T1-3（シートの機能の検証）が終わってから行う。T1-3 の検証コードが、テスト用スクリプトに入っている間は、始めない
- テスト用スクリプトの中身が、T1-3 のものから、この検証のものに置き換わる。メニューは「T1-4 検証」に変わり、T1-3 のメニューは消える。T1-3 のタブ（名前の先頭が「T1-3」）は残ってよく、この検証では触らない
- 前のメニュー（「T1-3 検証」など）が出る場合は、検証コードがまだ送られていないので、メインのセッションに伝える
- Apps Script のエディタの「トリガー」（左の時計のアイコン）に、T1-3 のトリガー（`trigEditPlain`、`timer_` など）が残っていたら、右端の「⋮」から「トリガーを削除」で消す。コードが入れ替わった後は、動かずにエラーのメールが届くだけになる
- ログインの状態を、次のように作れるようにしておく。8 つの開き方のうち、持っていない端末の開き方は飛ばしてよい
  - アカウント A だけでログインした Chrome のプロフィール: 右上のプロフィールのアイコンを押し、A のプロフィールを開く。そのプロフィールで、A 以外のアカウントがログインしていないことを `myaccount.google.com` で確かめる
  - A と B の両方でログインした Chrome のウィンドウ: A のプロフィールのウィンドウで、右上のプロフィールのアイコンを押し、「別のアカウントを追加」から B でログインする。この状態で、1 つのブラウザに A と B が入る。終わったら、B をログアウトする
  - B だけでログインした Chrome のプロフィール: T1-2 のプロフィールがあればそれを使う。なければ、プロフィールを作り、B でログインする（T1-2 の README の手順 4 の操作 1 と 2）
  - シークレットウィンドウ: Chrome の「⋮」（Mac はメニューバーの「ファイル」）から「新しいシークレット ウィンドウ」を開く。ログインしない。使い終わったら閉じる
  - iPhone の Safari、Android の Chrome: ふだんのブラウザで開く。ログインしているアカウントは、そのままでよい（何でログインしているかは、控えておく）
  - LINE の中のブラウザ: 自分宛てのトーク（LINE の「Keep メモ」か、自分だけのグループ）に、Web アプリの URL を送り、トークの中の URL を押して開く。ブラウザのアプリは開かず、LINE の中の画面で開くのが正しい。この URL は、自分だけが見られるトークにだけ貼る
- Web アプリの URL を、チャットや、ほかの人が見られる場所に貼らない。控えるのは、`/exec` の直前の 4 文字だけにする
- スマホは、iPhone と Android のどちらか、または両方ある場合は両方で確かめる。持っていないほうは飛ばす
- ブラウザは PC では Chrome を使う。所要時間は 90〜150 分ほど。画面が手順と違ったら、その時点の画面の文言をメインのセッションに渡す

## 画面の操作

調べる画面（Preact）の見方。

- 「どこから開いたか」: 開き方を 8 つから選ぶ。必ず先に選ぶ。一度「調べる」を押すと、その読み込みの間は変えられない
- 「調べる（1回の読み込みにつき1回）」: 幅（`viewport`、`viewport.html`）、localStorage と IndexedDB の保存、実行する人（`exec`）を調べて、ログに書く。再読み込みしたあとでないと、もう一度は押せない。画面の下の文字に、調べた値が出る
- 「往復の時間を測る」: 5KB、50KB、200KB の JSON を各 5 回返してもらい、時間を測る（W7）。1 回の読み込みで何度押してもよい
- 「控えを書く」: 画面を見て分かることを送る
  - 「画面の幅は端末に合って見えたか」: はい、いいえ。横に動かせたり、文字が極端に小さかったりしたら、いいえ（`user.width`）
  - 「ホーム画面に追加したときのアイコン」: 文言（例「画面の縮小」「G のマーク」「文字の頭文字」）を入れて「送る」（`user.homeicon`）
  - 「開けなかった開き方」と「その画面の文言」: 開けなかった開き方を選び、そのとき出た画面の文言を入れて「送る」。開けなかった開き方からは送れないので、開けた開き方（PC のシークレットなど）から送る（`user.cannotopen`）

画面が開いた時点で、自動でログに 3 行（`module`、`embed`、`classic`）が書かれる。開き方を選ぶ前に書かれるので、開き方の列は空になる。

## 手順

順番どおりに進める。各開き方で、共通の流れは次のとおり。

1. URL を開く。「どこから開いたか」を、いまの開き方に合わせて選ぶ
2. 「調べる」を押す（1 回目）。下の文字に値が出ることを確かめる
3. 再読み込みする。開き方を選び直して、「調べる」を押す（2 回目。保存が再読み込みで残るかを確かめる）
4. 画面のタブを閉じて、開き直す。開き方を選び直して、「調べる」を押す（3 回目。保存が開き直しで残るかを確かめる）
5. 「往復の時間を測る」を押す（PC の A だけでよい。ほかの開き方では、時間があれば）
6. 画面の幅が合って見えたかを、「控えを書く」で送る（スマホの開き方）

### 1. 準備を押し、承認する（PC、アカウント A）

- 場所: テスト用スプレッドシート（アカウント A、PC の Chrome）
- 操作
  1. テスト用スプレッドシートを開く。メニューに「T1-4 検証」が出るまで 10 秒ほど待つ。出なければ、再読み込みする
  2. 「T1-4 検証 ▸ 準備（ログのタブを作り、ID を保存する）」を押す
  3. 「承認が必要です」が出たら「続行」を押し、アカウント A を選ぶ。「このアプリは Google で確認されていません」が出たら、左下の「詳細」を押し、「（プロジェクト名）（安全でないページ）に移動」を押し、「許可」を押す。承認の画面に出る権限の一覧を控える
  4. もう一度「準備」を押す。「T1-4 検証ログ」タブができ、右下に「準備ができた」と出る
- 確かめること
  - 「T1-4 検証ログ」タブができたか。権限の一覧に何が出たか

### 2. Web アプリをデプロイする（PC、アカウント A）

- 場所: Apps Script のエディタ（アカウント A）
- 操作
  1. 「拡張機能 ▸ Apps Script」を押し、エディタを開く。左の「エディタ」で、ファイルの一覧に `Code`、`Logic`、`Page`（`.gs` と `.html`）があることを確かめる。コードは直さない
  2. 右上の青いボタン「デプロイ」を押し、「新しいデプロイ」を押す
  3. 左上の歯車のアイコンを押し、「ウェブアプリ」を押す。説明に「T1-4」と入力する
  4. 「次のユーザーとして実行」を「自分」にする。「アクセスできるユーザー」を「全員」にする
  5. 「デプロイ」を押し、承認を求められたら承認する
  6. 表示された URL（`https://script.google.com/macros/s/…/exec`）をコピーし、メモ帳に貼る。先頭に「exec:」と書く。URL の `/exec` の直前の 4 文字を控える。この URL はチャットに貼らない
  7. 「デプロイ」を押し、「デプロイをテスト」を押す。出た URL（末尾が `/dev`）をコピーし、メモ帳に「dev:」として貼る。この URL は、アカウント A のブラウザでだけ開ける
  8. LINE の中のブラウザで開くために、「exec:」の URL を、自分宛てのトーク（Keep メモなど）に送る。この URL は、自分だけが見られるトークにだけ貼る
- 確かめること
  - デプロイを作れたか。`/dev` の URL が出たか

### 3. PC の Chrome、アカウント A だけでログインして開く（PC、アカウント A）

W1（埋め込み）、W2（Vite の出力）、W4、W6、W7、W8 の確かめ。

- 場所: アカウント A だけでログインした Chrome のプロフィール
- 操作
  1. メモ帳の「exec:」の URL を、新しいタブで開く。調べる画面が出ることを確かめる。出なければ、画面の文言を控える
  2. 「どこから開いたか」で「PC の Chrome、アカウント A だけでログイン」を選ぶ。共通の流れの操作 2 から 4 を行う
  3. 「往復の時間を測る」を押す。3 つの大きさが終わるまで待つ（下の文字に、5KB、50KB、200KB の時間が出る）
  4. 「dev:」の URL を新しいタブで開く。「どこから開いたか」で、同じ開き方を選び、「調べる」を押す。`exec` の行に `dev` が出ることを、下の文字で確かめる
- 確かめること
  - 画面が開いたか（W8）。下の文字に、`exec:` の結果（`kind`、`effectiveIsOwner`、`read`、`wrote`）が出たか（W6）
  - 再読み込みと開き直しで、保存の値の「前の値」が「あり」になったか（W4）
  - 往復の時間（W7）

### 4. PC の Chrome、アカウント A と B の両方でログインして開く（PC、A と B）

W6、W8、W9 の確かめ。T1-2 で、複数のアカウントでログインしたブラウザで開けなかった可能性がある。

- 場所: A と B の両方でログインした Chrome のウィンドウ
- 操作
  1. 始める前にの手順で、A のプロフィールに B を追加でログインする。`myaccount.google.com` で、2 つのアカウントがログインしていることを確かめる
  2. メモ帳の「exec:」の URL を、新しいタブで開く
  3. 開いたら、「どこから開いたか」で「PC の Chrome、アカウント A と B の両方でログイン（複数のアカウント）」を選び、共通の流れの操作 2 から 4 を行う
  4. 開けなかったら（「現在、ファイルを開くことができません」などの画面が出たら）、画面の文言をそのまま控え、スクリーンショットも撮る。この開き方からは、調べる画面の控えを送れないので、手順 6 のシークレットウィンドウから送る
  5. 終わったら、B のアカウントをログアウトする
- 確かめること
  - 開けたか。開けなかった場合の、画面の文言

### 5. PC の Chrome、アカウント B だけでログインして開く（PC、アカウント B）

- 場所: B だけでログインした Chrome のプロフィール
- 操作
  1. B のプロフィールの Chrome で、`myaccount.google.com` で B だけがログインしていることを確かめる
  2. メモ帳の「exec:」の URL を開く。開けなかったら、画面の文言を控える
  3. 開けたら、「どこから開いたか」で「PC の Chrome、アカウント B だけでログイン」を選び、共通の流れの操作 2 から 4 を行う。`exec` の結果（`effectiveIsOwner` が `true` か）を控える
- 確かめること
  - 開けたか。開けた場合、実行する人が持ち主（A）になっているか（W6）

### 6. PC の Chrome、シークレットウィンドウで開く（PC、ログインなし）

- 場所: Chrome のシークレットウィンドウ
- 操作
  1. シークレットウィンドウを開く。ログインしない
  2. メモ帳の「exec:」の URL を開く
  3. 「どこから開いたか」で「PC の Chrome、シークレットウィンドウ（ログインしていない）」を選び、共通の流れの操作 2 から 4 を行う。シークレットウィンドウは、タブを閉じても同じウィンドウの中なら記憶が残る。開き直しは、シークレットウィンドウをすべて閉じてから、新しく開いて行う
  4. 手順 4 と 5 で開けなかった開き方があれば、調べる画面の「控えを書く」の「開けなかった開き方」でその開き方を選び、控えた画面の文言を入れて「送る」。開けなかった開き方ごとに行う
- 確かめること
  - 開けたか。控えた文言を送ったか

### 7. iPhone の Safari で開く（スマホ）

- 場所: iPhone の Safari
- 操作
  1. Safari で、メモ帳（自分宛てのトーク）の「exec:」の URL を開く。Google にログインしていなければ、ログインする必要はない
  2. 「どこから開いたか」で「iPhone の Safari」を選び、共通の流れの操作 2 から 4 を行う
  3. 画面の幅が端末に合って見えたかを、「控えを書く」で送る（はい、いいえ）
  4. Safari の共有のボタンから「ホーム画面に追加」を押す。ホーム画面にできたアイコンを見て、何だったか（例「画面の縮小」「G のマーク」「文字の頭文字」）を、「控えを書く」の「ホーム画面に追加したときのアイコン」に入れて送る
- 確かめること
  - 開けたか。幅が合って見えたか。保存が残ったか。ホーム画面のアイコンは何だったか

### 8. iPhone の LINE の中のブラウザで開く（スマホ）

- 場所: iPhone の LINE
- 操作
  1. 手順 2 で自分宛てのトークに送った「exec:」の URL を、LINE の中で押して開く。LINE の外のブラウザ（Safari）に切り替わった場合は、画面の右上などで「ブラウザで開く」を押していないことを確かめる

### 作りと決めたこと

- ログは、列全体を「書式なしテキスト」にしてから書く。`=` で始まる値も数式にならない
- ログに書くメールアドレスと Web アプリの URL は、`log_` が書く前に伏せる。実行する人が持ち主かは、比べた結果の真偽だけを書く
- `recordFact` と `probeExec` は、Web アプリを開いた誰でも呼べる。受け取った値が文字列でなければ断り、ログに書くだけで、ほかのシートの値は返さない。検証の間だけのコードで、本番には使わない
- 埋め込みは、`embedCatalog_` が目印の位置を探して、置き換える（`String.replace` の `$&` などの解釈を避ける）。`<` を `<` に、U+2028 と U+2029 をエスケープする
- 調べる画面の再読み込みと開き直しは、sessionStorage の印（`t14-session-mark`）で見分ける。印があれば再読み込み、なければ開き直し。sessionStorage が使えなければ `unknown`
- 実行する人のシートの書き込みの確かめは、ログのタブの `H1` に時刻を書く

### 権限の範囲（`oauthScopes`）

`gas/appsscript.json` は、スプレッドシート（`spreadsheets`）、メニュー（`script.container.ui`）、`ScriptApp.getService().getUrl()`（`script.scriptapp`）、`Session.getEffectiveUser()`（`userinfo.email`）を持つ。`script.scriptapp` が `getUrl()` に要るかどうかは、確かめていない。
