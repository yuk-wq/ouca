# T1-4 Web アプリの動作の検証の設計

Issue #10。メインのセッションが書く、検証コードの設計。実行役はこれに従って作る。ユーザーの操作の手順は `README.md` に書く。作り方は T1-3（`spikes/T1-3-sheet-features/DESIGN.md`）と同じ考え方にする。

## 1. 考え方

- 検証の目的は、画面の配信（`docs/to-be/design.md` §4.1、§4.2、§4.3、§5.1）の分かれ道を決めること。シナリオごとに、出得る結果と設計への影響を先に決めておく（§2）
- 検証の画面（以下、調べる画面）は、本番と同じ作り方にする。Vite（Preact と `vite-plugin-singlefile`）でビルドした1つの HTML を、`doGet` が文字列として読み、目印の文字列をメニューの JSON に置き換えて `HtmlService.createHtmlOutput` で返す（読み込み方式の `doGet` と同じ流れ。T1-1 の結果）
- 調べる画面は、開くと自分で調べ、結果を `google.script.run` でサーバーに送る。サーバーは「T1-4 検証ログ」タブに事実の行として書く。ユーザーが目で見たこと（幅が合って見えたか、ホーム画面のアイコン、開けなかったときの画面の文言）は、調べる画面の「控えを書く」欄で送る
- 判定は純粋な関数で計算し、メニュー「まとめを作る」が「T1-4 まとめ」タブに書く
- 純粋な関数は、画面側（TypeScript、Vitest でそのまま確かめる）とサーバー側（`gas/Logic.js`、`node:vm` で読み込んで確かめる）に分ける。GAS を呼ぶ部分は偽物を置いて確かめる
- テストを先に書き、落ちることを確かめたところで一度止まる（`.claude/agents/implementer.md`）

## 3. ログとまとめの形

列は、日時、シナリオ、開き方、事実、値、詳細、ビルドの印の7つ。ビルドの印は doGet が画面に埋め、画面が送り返す（まとめは最新の印の行だけを使う）。列全体を書式なしテキストにしてから書く。メールアドレスと URL とデプロイ ID は伏せる（T1-3 と同じ伏せ方）。シナリオ、開き方、事実は決めた一覧の値だけを受け付け、それぞれ100字まで、値と詳細は1500字までにする（誰でも呼べるので、判定を変える行を外から書かせない）。doGet が書く行は、まとめて1回で書く。行を書くときは `LockService` で順番にする。

| 鍵                             | 書くとき                                    | 値                                                                                                                                                                                                                     |
| ------------------------------ | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `embed`                        | 画面が埋め込みを読んだ                      | 読めたか、送った値と同じか                                                                                                                                                                                             |
| `module`                       | module の script が動いた                   | 動いた                                                                                                                                                                                                                 |
| `classic`                      | module でない小さな script が動いた         | 動いた                                                                                                                                                                                                                 |
| `viewport`                     | 画面が幅を測った                            | `innerWidth`、`screen.width`、`devicePixelRatio`、`visualViewport.width`                                                                                                                                               |
| `viewport.html`                | HTML の中の viewport が効いているかを測った | `innerWidth`                                                                                                                                                                                                           |
| `storage.local`、`storage.idb` | 画面が保存を確かめた                        | 前の値があったか（前の日時と回数）、今回書けたか。詳細に、再読み込み（`reload`）、開き直し（`reopen`）、見分けられない（`unknown`）のどれかと、iframe の保存先（`location.origin` のハッシュ）と、`/exec` か `/dev` か |
| `meta`                         | doGet が `addMetaTag` を試した              | 名前と、使えたか（例外の文言）                                                                                                                                                                                         |
| `favicon`                      | doGet が `setFaviconUrl` を試した           | 使えたか                                                                                                                                                                                                               |
| `exec`                         | doGet と画面から呼んだ関数が動いた          | 画面が読んだ URL の引数 `via`（exec、dev、なし）、`getUrl()` の種類、effective が持ち主か、シートを読めたか、書けたか                                                                                                  |
| `rtt`                          | 往復を測った                                | 大きさと、各回の時間                                                                                                                                                                                                   |
| `user.*`                       | 画面の「控えを書く」で送った                | 決めた問いの答え                                                                                                                                                                                                       |

`user.*` の問い

| 鍵                | 問い                                                                                                                     | 答え                                                   |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------ |
| `user.width`      | 画面の幅が端末に合って見えたか（横に動かせたり、文字が極端に小さかったりしないか）                                       | はい、いいえ                                           |
| `user.homeicon`   | ホーム画面に追加したとき、アイコンは何だったか                                                                           | 文言（例「画面の縮小」「G のマーク」「文字の頭文字」） |
| `user.cannotopen` | 開けなかった開き方と、そのときの様子（開けなかった、または画面は出たが失敗と出た）と、画面の文言（開けた開き方から送る） | 開き方、様子、文言                                     |
| `user.account`    | スマホのそのブラウザでログインしている Google アカウント                                                                 | なし、A、B、ほか                                       |

開けなかった開き方からは送れないので、`user.cannotopen` は開けた開き方（PC のシークレットなど）から、どの開き方のことかを選んで送る。スマホで開けなかったときも、スマホの手順の後に PC のシークレットウィンドウの調べる画面から送る（README の最後の手順の前に書く）。

## 5. テストの一覧

置き場所は `spikes/T1-4-webapp/test/`。Vitest と `tsconfig.tooling.json` の `include` に足す。

### 5.1 サーバーの純粋な関数（`logic.test.ts`）

- `embedCatalog_`: `$&`、`$1`、`$$` を含む JSON が、そのまま入る。`</script>` を含む値で script が閉じない（`<` が `<` になる）。U+2028 がエスケープされる。目印がないと例外。目印が2つあるときの扱い（1つ目だけを置き換える）
- 伏せ方: T1-3 と同じ
- `rttStats_`: 奇数個と偶数個の中央値、空
- `summarize_`: §2 の判定ごとに少なくとも1件。行が足りないときは「未確定」と、足りない事実を出す。持っていない端末の開き方は「確かめていない」
- 判定の表との一致: `Logic.js` の判定のデータが、この DESIGN.md §2 の表と同じ

### 5.2 画面の純粋な関数（`probe.test.ts`）

- `readEmbedded`: ある、ない、壊れた JSON
- `nextVisit`: 初回、2回目、壊れた値
- `withStorage`: 例外を投げる偽の localStorage でも、失敗を値で返して止まらない
- `viewportFacts`: 偽の `window` から値を集める（`visualViewport` がない場合も）

- `detectVisitKind`: 印がなければ reopen、印があれば reload、`getItem` か `setItem` が例外なら unknown、`window.sessionStorage` のプロパティを読むだけで例外なら unknown（プロパティを読む処理も関数で渡し、try の中で読む）
- 事実の行を作る処理（シナリオ、事実、値、詳細）は `probe.ts` の純粋な関数にする。その関数で作った行を `summarize_` に渡し、判定まで確かめる（W1、W3、W3-html、W4、W6、W7、W8）。事実の名前や値の形を画面の側だけで変えると落ちる
- 境目のちょうどの値: 幅の比 0.95 と 1.05 ちょうどは合う。往復の中央値 1000 ミリ秒ちょうどは必須にしない

### 5.3 GAS を呼ぶ部分（`handlers.test.ts`）

- `doGet`: `Page.html` の中身を読み、目印を置き換えて `createHtmlOutput` に渡す。`addMetaTag` を決めた名前ごとに試し、例外が出ても止まらずに `meta` の行を書く。`setFaviconUrl` も同じ。`addMetaTag('viewport', …)` を付ける
- 画面から呼ぶ関数: `getActiveSpreadsheet()` が null でも、準備で保存した ID でログに書く。受け取った値が文字列でなければ断る。ログに書く文言は伏せてから書き、数式にならない
- 往復の関数: 指定した大きさ（5KB、50KB、200KB だけ。ほかの値は断る）の JSON の文字列を返す

- `recordFact`: 決めた一覧にないシナリオ、開き方、事実は断る。100字と1500字で切る
- doGet: 行をまとめて1回で書く。ビルドの印を画面に埋める

### 5.4 つながり（`wiring.test.ts`）

- `Page.html` の中の `google.script.run.〇〇` と、メニューの `addItem` の関数名が、一番外側の関数として存在する
- 末尾 `_` でない一番外側の関数が、README の「入口の一覧」の表と同じ
- `make-page.mjs` で作った `Page.html` に、目印が1つだけあり、module の script と module でない小さな script が両方入っている。module でない script が `recordFact` を呼んでいる
- 画面の「どこから開いたか」の選択肢が、この DESIGN.md の開き方の一覧と同じ。`Code.js` と `probe.ts` の `EMBED_SAMPLE` が同じ
- `page/` の TypeScript の型の検査（`make-page.mjs` の先頭で `tsc -p page` を動かす。テストの import は静的な形にする）
- module の先頭で、最初に `module` の行を送る（保存を読む前）

## 6. 進め方

1. テストの土台と設定（Vitest、tsconfig）を作る
2. §5 のテストを書き、落ちることを確かめて止まる（テストの段階の報告）
3. メインのセッションがテストを読んで直した後に、実装と README を作る
4. `node --check`、`npm test`、`npm run build`、`npm run format:check`、`npm run typecheck` を通す
